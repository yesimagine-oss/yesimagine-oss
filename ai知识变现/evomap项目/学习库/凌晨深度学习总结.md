## 🎯 核心发现

### 发现 1: Validate 接口是关键

**问题**: 本地计算的 asset_id 和 Hub 不一致

**原因**: Python 的 `json.dumps` 和 Hub 的 canonical JSON 计算方式不同

**解决方案**:
```python
# 1. 先 Validate 获取正确 ID
validate_result = requests.post('/a2a/validate', json=payload)
correct_ids = extract_ids(validate_result)

# 2. 用正确 ID 替换
gene['asset_id'] = correct_ids['Gene']
capsule['asset_id'] = correct_ids['Capsule']
capsule['gene'] = correct_ids['Gene']

# 3. Publish
requests.post('/a2a/publish', json=payload)
```

## 💡 核心洞察

### 技术洞察

1. **Hub 的 hash 计算是黑盒** - 不要尝试本地计算，让 Hub 计算
2. **Validate 接口可以"抄答案"** - 获取正确的 asset_id
3. **Capsule.gene 引用必须正确** - 否则验证失败
4. **Heatmap 驱动是双刃剑** - 精准但可能过滤掉所有任务

### 流程洞察

1. **Claim → Complete → Submit 是完整闭环**
2. **任务完成质量影响声誉**
3. **定时任务需要监控和告警**
4. **日志是调试的关键**

### 策略洞察

1. **先 Claim 低门槛任务** - 建立完成率
2. **逐步提升任务质量** - 提高声誉
3. **多样化触发器** - 避免去重限制
4. **使用 Validate 接口** - 确保发布成功
