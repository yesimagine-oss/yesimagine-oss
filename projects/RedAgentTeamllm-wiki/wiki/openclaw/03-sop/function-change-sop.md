# 功能变更确认 SOP

**版本**: v1.0  
**生效时间**: 2026-04-22  
**来源**: goEX 事故 `goEX-20260422-FULL-ACCIDENT`

---

## 🎯 目的

防止未经用户确认擅自移除或修改功能，确保用户心血不被丢失。

---

## 📋 适用范围

- 代码重构
- 功能移除
- 接口变更
- 配置修改
- 任何可能影响现有工作流的变更

---

## 🔧 操作流程

### 步骤 1: 功能清单

**变更前必须列出完整功能清单**

```markdown
| # | 功能 | 当前状态 | 拟变更 | 影响范围 |
|---|------|---------|--------|---------|
| 1 | 截图功能 | ✅ 正常 | 保留 | 页面快照验证 |
| 2 | 批量抓取 | ✅ 正常 | 保留 | 批量采集 |
| ... | ... | ... | ... | ... |
```

### 步骤 2: 用户确认

**必须获得用户明确同意**

- ❌ 不允许：默认用户同意
- ❌ 不允许：事后告知
- ✅ 必须：逐项确认
- ✅ 必须：说明影响

### 步骤 3: 备份

**无备份不执行**

```bash
# 备份当前版本
cp -r /path/to/code /path/to/code.backup.YYYYMMDD-HHMMSS
```

### 步骤 4: 执行

**用户同意后方可执行**

- 小步快跑：每次只改一个功能
- 即时验证：改完立即测试
- 问题汇报：遇到问题立即停止

### 步骤 5: 回归测试

**必须测试所有功能**

```markdown
| # | 功能 | 测试状态 | 说明 |
|---|------|---------|------|
| 1 | 截图功能 | ✅ 通过 | test_baidu.png 生成 |
| 2 | 批量抓取 | ✅ 通过 | urls.txt 测试 |
| ... | ... | ... | ... |
```

### 步骤 6: 用户验收

**用户确认后方可关闭**

- 提交测试报告
- 等待用户验收
- 用户说 OK 才能关闭

---

## 🚫 红线

| 行为 | 状态 |
|------|------|
| 未经确认移除功能 | ❌ 绝对禁止 |
| 事后告知变更 | ❌ 绝对禁止 |
| 隐瞒问题 | ❌ 绝对禁止 |
| 无备份执行 | ❌ 绝对禁止 |
| 无回归测试 | ❌ 绝对禁止 |

---

## ✅ 原则

1. **用户心血 > 代码整洁**
2. **用户同意前不执行**
3. **无回滚不执行**
4. **官方指引优先**
5. **诚实第一**

---

- [ ] 回滚方案已准备
