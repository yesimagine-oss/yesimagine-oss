## 🎯 核心突破

### 问题发现

用 v2.0 模板（带表格、状态判定规则）验收用户采样，发现：
- ❌ 状态仍填🟢（实际🟡）
- ❌ 覆盖仍写完整（实际部分）
- ❌ 候选仍写无（实际 2 条）

**根本原因**: 模板约束力不够，像指南不是法律。

---

## 📊 深度对比分析

### 版本 1（用户原始版）核心优势

| 优势 | 具体体现 | 效果 |
|------|---------|------|
| **防造假机制** | 10 条硬性要求 + 8 条禁止项 | 明确什么不能做 |
| **证据等级定义** | 4 级清晰（原文 + 实测/原文-only/实测-only/转述） | 不会混淆 |
| **规则嵌入每部分** | 每部分都有"必须包含""禁止""若...则..." | 填写时自检 |
| **约束力强** | 多次使用"禁止""不得" | 心理威慑 |
| **聚焦真实** | 核心是"证据"不是"格式" | 方向正确 |

### 版本 2（我优化版）核心缺陷

| 缺陷 | 具体体现 | 后果 |
|------|---------|------|
| **约束力弱** | 仅状态判定规则 | 可遵守可不遵守 |
| **禁止项缺失** | 无明确"禁止" | 容易美化 |
| **规则分散** | 仅在表头提及 | 填写时易忽略 |
| **聚焦格式** | 表格美观 | 忽略真实 |

## 🧬 内化原则（Sovereign Evolution）

### 原则 1: 约束力 > 美观度

```
❌ 错误：表格好看、结构清晰
✅ 正确：规则明确、禁止项清晰
```

**行动**: 验收时优先检查是否违反禁止项，不是格式是否正确。

---

### 原则 2: 防造假机制必须嵌入

```
必须嵌入的机制：
1. 原始输出必须逐字保留
2. 未进入原始采样区的内容不得进入资产
3. 没有证据禁止写"全覆盖"
4. 候选事实不得写入 Gene/Capsule
```

**行动**: 验收时逐项核对这 4 条红线。

---

### 原则 3: 证据等级必须清晰

```
高可信：原文证据 + 实测证据同时具备
中可信：仅有原文证据，未实测
低可信：仅有转述、总结、推断
```

**行动**: 验收时检查证据等级是否与内容匹配。

---

### 原则 4: 状态判定必须基于客观规则

```
🟢 完整 = 4 项可执行内容 ≥3 项「已提取」
🟡 待深度 = 4 项可执行内容 ≥3 项「未提取」
🔴 仅结构 = 仅有标题/结构，无代码块
```

**行动**: 验收时重新计算，不信任填写的状态。

---

### 原则 5: 结论边界必须诚实

```
❌ 错误：已完整提取全部可执行信息
✅ 正确：已提取格式化规则和 7 项字段，缺鉴权方法和测试命令
```

**行动**: 验收时检查是否明确说明"缺什么"。

## 📋 验收 SOP（进化后）

### 第一步：检查原始采样区

- [ ] 有 URL+ 原文摘录
- [ ] 有命令原文 + 原始输出
- [ ] 命令语法正确（管道符、引号）
- [ ] 代码块完整提取

### 第二步：检查覆盖证据

- [ ] 已发现/已抓取/排除列表完整
- [ ] "未抓取区域"如实填写
- [ ] 可执行内容 4 项如实填写

### 第三步：检查状态判定

- [ ] 计算 4 项可执行内容
- [ ] 验证🟢🟡🔴是否正确
- [ ] 不正确则修正

### 第四步：检查候选事实

- [ ] 未验证内容是否列入候选
- [ ] 可信度是否合理（0.80-0.90）
- [ ] 建议是否具体

### 第五步：检查 Gene/Capsule

- [ ] validate_command 是否来自事实清单
- [ ] executable_code 是否仅包含已验证动作
- [ ] confidence 是否≥0.9

### 第六步：检查评估报告

- [ ] 证据支持分类正确
- [ ] 可执行性统计匹配
- [ ] 结论边界诚实（说明缺什么）
