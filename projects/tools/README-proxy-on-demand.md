# 代理按需启动方案对比

**创建时间**: 2026-03-29 19:40

---

## 📊 方案对比

### 方案 1: 定时扫描（已实现，不推荐）

**原理**: 每分钟扫描一次端口连接

| 维度 | 评分 | 说明 |
|:---|:---|:---|
| **响应速度** | ⭐⭐⭐ | 最多等 1 分钟 |
| **资源占用** | ⭐⭐ | 每分钟扫描一次 |
| **实现难度** | ⭐⭐⭐⭐⭐ | 简单 |
| **可靠性** | ⭐⭐⭐⭐ | 较可靠 |

**问题**:
- ❌ 浪费资源
- ❌ 不是真正按需
- ❌ 有延迟

---

### 方案 2: 端口监听触发（推荐）

**原理**: 监听 7890 端口，有连接请求时自动启动

**脚本**: `tools/proxy-autostart.py`

| 维度 | 评分 | 说明 |
|:---|:---|:---|
| **响应速度** | ⭐⭐⭐⭐⭐ | 秒级响应 |
| **资源占用** | ⭐⭐⭐⭐⭐ | 几乎为零 |
| **实现难度** | ⭐⭐⭐⭐ | 较简单 |
| **可靠性** | ⭐⭐⭐⭐⭐ | 非常可靠 |

**优势**:
- ✅ 真正按需（有请求才启动）
- ✅ 零延迟（立即启动）
- ✅ 不浪费资源（无请求不扫描）

---

### 方案 3: 浏览器扩展触发（最佳）

**原理**: 浏览器访问外网失败时自动触发

| 维度 | 评分 | 说明 |
|:---|:---|:---|
| **响应速度** | ⭐⭐⭐⭐⭐ | 即时 |
| **资源占用** | ⭐⭐⭐⭐⭐ | 零占用 |
| **实现难度** | ⭐⭐ | 复杂 |
| **可靠性** | ⭐⭐⭐⭐⭐ | 最佳 |

**问题**:
- ❌ 需要开发浏览器扩展
- ❌ 需要用户安装

---

### 方案 4: 系统透明代理（高级）

**原理**: 使用 iptables 拦截外网请求

| 维度 | 评分 | 说明 |
|:---|:---|:---|
| **响应速度** | ⭐⭐⭐⭐⭐ | 即时 |
| **资源占用** | ⭐⭐⭐⭐⭐ | 零占用 |
| **实现难度** | ⭐ | 非常复杂 |
| **可靠性** | ⭐⭐⭐⭐⭐ | 最佳 |

**问题**:
- ❌ 需要 root 权限
- ❌ 配置复杂
- ❌ 可能影响其他应用

## 🎯 推荐方案

**理由**:
1. ✅ 实现简单
2. ✅ 真正按需
3. ✅ 资源占用低
4. ✅ 响应速度快

**使用方法**:


## 📋 实施步骤

### 方案 2 实施

**1. 停止旧服务**:
```bash
pkill -f proxy-manager.py
```

**2. 启动新服务**:
```bash
nohup python3 tools/proxy-autostart.py > logs/proxy-autostart.log 2>&1 &
```

**3. 验证服务**:
```bash
ps aux | grep proxy-autostart
curl http://127.0.0.1:7890  # 应该触发自动启动
```

**4. 查看日志**:
```bash
tail -f logs/proxy-autostart.log
```

## 🔄 工作流程

```
用户访问外网
   ↓
浏览器请求 127.0.0.1:7890
   ↓
proxy-autostart.py 检测到连接
   ↓
检查 Clash 是否运行
   ↓
如未运行 → 自动启动
   ↓
浏览器请求成功
   ↓
10 分钟闲置 → 自动关闭
```
