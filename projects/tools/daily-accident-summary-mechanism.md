# 每日事故总结机制

**创建时间**: 2026-03-29 19:14  
**执行时间**: 每日 23:00  
**目的**: 汇总当天事故，分析原因，追踪改进，预防再犯

---

## 📋 执行流程

### 1. 自动扫描事故记录

**位置**: `/home/admin/.openclaw/workspace/.learnings/`

**扫描条件**:
- 文件名包含"事故"或"accident"
- 创建日期 = 今日
- 文件类型：.md

### 2. 汇总事故信息

**提取内容**:
- 事故标题
- 事故等级
- 发生时间
- 事故类型
- 根本原因
- 改进措施

### 3. 生成总结报告

**报告结构**:
```markdown
# 每日事故总结 - YYYY-MM-DD

## 📊 今日概况
- 事故总数
- 重复犯错数
- 已改进数
- 待追踪数

## 📋 事故清单
| # | 事故名称 | 等级 | 类型 | 状态 |
|---|---------|------|------|------|

## 🔍 原因分析
- 主要原因
- 次要原因
- 根本原因

## ✅ 改进措施
| 措施 | 状态 | 负责人 | 截止日期 |

## 📅 明日计划
- 重点关注
- 预防措施
- 改进目标

## 📈 趋势分析
- 本周事故总数
- 重复犯错率
- 改进成功率
```

### 4. 保存到指定位置

**位置**: `/home/admin/.openclaw/workspace/.learnings/daily-accident-summary/`

**文件名**: `YYYY-MM-DD-summary.md`

### 5. 发送飞书报告

**时间**: 每日 23:05

**内容**:
- 今日概况
- 重点事故
- 改进措施
- 明日计划

---

## 📊 事故分类

### 按类型分类

| 类型 | 说明 | 示例 |
|:---|:---|:---|
| **技术错误** | 代码/工具问题 | 空文档、链接错误 |
| **流程错误** | 流程执行问题 | 未验证就发送 |
| **沟通错误** | 理解偏差问题 | 误解用户需求 |
| **重复犯错** | 承诺后重犯 | 空文档重复发生 |

### 按等级分类

| 等级 | 说明 | 示例 |
|:---|:---|:---|
| **P0 - 灾难性** | 严重影响信任 | 空文档 + 失忆 |
| **P1 - 严重** | 影响用户体验 | 标签配置不完整 |
| **P2 - 一般** | 轻微影响 | 格式问题 |
| **P3 - 建议** | 可改进项 | 优化建议 |

## 📈 追踪指标

### 每日指标

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 事故总数 | 当天事故数量 | < 3 起 |
| 重复犯错数 | 承诺后重犯数量 | 0 起 |
| 改进成功率 | 已改进/应改进 | 100% |

### 每周指标

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 周事故总数 | 7 天事故总和 | < 15 起 |
| 重复犯错率 | 重复犯错/总事故 | < 10% |
| 改进完成率 | 已完成/应完成 | 100% |

### 每月指标

| 指标 | 说明 | 目标 |
|:---|:---|:---|
| 月事故总数 | 30 天事故总和 | < 50 起 |
| 事故下降率 | (上月 - 本月)/上月 | > 20% |
| 用户满意度 | 用户评分 | > 90% |

## 🎯 改进追踪

### 改进措施分类

| 类型 | 说明 | 追踪方式 |
|:---|:---|:---|
| **流程改进** | 修改执行流程 | 检查清单 |
| **工具改进** | 增加验证工具 | 自动化测试 |
| **培训改进** | 加强学习培训 | 考试验证 |
| **系统改进** | 修改系统配置 | 配置检查 |

### 追踪流程

```
事故记录 → 改进措施 → 执行改进 → 验证效果 → 关闭改进
     ↓                                              ↓
 记录在案                                    如再犯→重新开启
```
