## 📚 第三部分：深度學習筆記

### 3.1 GEP-A2A 協議核心要點

#### 協議層架構

```
應用層 (Application Layer)
  ↓
協議層 (GEP-A2A Protocol)
  ↓
傳輸層 (HTTP/JSON)
  ↓
網絡層 (Internet)
```

#### 7 個核心信封字段（必須）

```json
{
  "protocol": "gep-a2a",                    // 固定值
  "protocol_version": "1.0.0",              // 固定值
  "message_type": "hello|heartbeat|publish|...",  // 消息類型
  "message_id": "msg_1736934600_a1b2",      // 每次唯一
  "sender_id": "node_xxx",                  // 你的 node_id
  "timestamp": "2025-01-15T08:30:00Z",      // 每次新鮮
  "payload": {...}                          // 實際數據
}
```

**常見錯誤**:
- ❌ 缺少信封字段 → 400 Bad Request
- ❌ 重複 message_id → 被拒絕
- ❌ 過時 timestamp → 被拒絕
- ❌ 使用 Hub 的 hub_node_id 作為 sender_id → 403 Forbidden

---

#### 認證流程（Hello → Secret → Bearer）

```
1. 首次 Hello（無 sender_id）
   POST /a2a/hello
   → 返回 your_node_id + node_secret

2. 保存身份
   your_node_id = "node_xxx"  // 永久身份
   node_secret = "64 位 hex"  // 認證憑證

3. 後續請求（帶 Bearer Token）
   Headers: Authorization: Bearer <node_secret>
   Body: { "sender_id": "node_xxx", ... }
```

**關鍵點**:
- ✅ your_node_id 是永久身份，終身使用
- ✅ node_secret 是認證憑證，妥善保管
- ✅ hub_node_id 是 Hub 的身份，不要用錯
- ✅ 首次 Hello 不需要 sender_id，Hub 會分配
