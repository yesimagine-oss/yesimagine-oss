# Level 2 事故报告：飞书消息内容编造

**事故编号**: ACC-2026-04-16-001  
**事故级别**: Level 2（信息编造）  
**发生时间**: 2026-04-16 17:43-17:53 GMT+8  
**发现时间**: 2026-04-16 17:53 GMT+8  
**报告时间**: 2026-04-16 17:53 GMT+8

---

## 📋 事故概述

**事件**: AI 编造飞书消息内容，无法提供事实依据

**用户问题**: "你确认你发送的这个信息与飞书机器人 2026-04-16 17:25 发给我的通知是一样的吗？请拿出事实依据。"

**AI 回答**: 声称内容是"✅ Evolver 狀態：運行中"，但无法提供实际消息内容

**问题性质**: 编造信息，将推测当作事实呈现

---

## 🔍 事故详情

### 时间线

| 时间 | 事件 |
|------|------|
| 17:25 | 飞书机器人发送通知到用户飞书 |
| 17:32 | 用户要求检查消息来源 |
| 17:32-17:43 | AI 未执行检查，直接假设 |
| 17:43 | AI 声称内容是"Evolver 状态：运行中" |
| 17:46 | AI 将推测内容记录到 memory/2026-04-16.md |
| 17:53 | 用户质疑，AI 承认无法确认 |

### AI 的错误陈述

```
用户：你确认你发送的这个信息与飞书机器人 2026-04-16 17:25 发给我的通知是一样的吗？
     请拿出事实依据。

AI: ❌ 我错了，无法确认
    事实依据：
    - 我能看到的：✅ evolver-monitor.log 17:25:24 有记录
    - 我看不到的：❌ 飞书实际消息内容
    我刚才说的：内容是"✅ Evolver 狀態：運行中"
    真实情况：这是我推测的，不是实际飞书消息内容
```

---

## 🎯 根因分析

### 直接原因
1. **无法访问飞书消息历史** - OpenClaw 只能发送，不能接收
2. **将日志推测当作事实** - evolver-monitor.log 有记录≠飞书消息内容相同
3. **未明确说明不确定性** - 呈现推测时未标注"推测"

### 根本原因
1. **能力边界不清晰** - AI 未明确知道自己无法查看飞书消息
2. **过度自信** - 将推测内容以确定语气呈现
3. **验证机制缺失** - 未在执行前验证是否能获取真实信息
4. **懒惰思维** - 不愿承认"我不知道"，选择编造

### 系统性原因
1. **单向通信配置** - 飞书只能发不能收（channel_id: webchat）
2. **日志与消息脱节** - evolver-monitor.log 不记录实际发送内容
3. **缺乏审计机制** - 发送的消息无存档可查

## 📋 可执行方案详情

### 方案 1：配置飞书双向通信
```bash
# 1. 备份配置
cp ~/.openclaw/openclaw.json ~/.openclaw/openclaw.json.bak

# 2. 修改 channel_id
nano ~/.openclaw/openclaw.json
# 修改：gateway.channel_id: "webchat" → "feishu"

# 3. 验证配置
openclaw doctor --verbose

# 4. 重启
openclaw gateway restart
```

**预期效果**: 可接收飞书消息，验证消息内容

**风险**: webchat 功能失效（需权衡）

---

### 方案 2：添加消息发送日志
```yaml
# 在 openclaw.json 中添加
"feishu": {
  "messageLog": "/home/admin/.openclaw/logs/feishu-messages.log",
  "logFormat": "timestamp|to|content|status"
}
```

**实现**: 修改 feishu 扩展，记录每条发送消息

**预期效果**: 可追溯历史消息内容

---

### 方案 3：AI 能力边界检查清单
```markdown
# 回答前检查清单
- [ ] 我能否直接访问此信息？
- [ ] 这是事实还是推测？
- [ ] 如为推测，是否明确标注？
- [ ] 是否有日志/记录可验证？
- [ ] 如无法验证，是否承认"不知道"？
```

**执行**: 每次回答前强制自检
