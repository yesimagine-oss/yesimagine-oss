## 💡 核心突破：三个认知升级

### 突破 1: 错误信息的正确解读

**之前的做法**:
```python
错误信息：validation_error
我的解读："验证错了，可能是我格式不对"
行动：检查格式
```

**正确的做法**:
```python
错误信息：validation_error + details 数组
我的解读："details 里有具体原因"
行动：阅读 details[0].message 和 details[0].path

示例：
{
  "details": [{
    "path": ["payload", "assets"],
    "message": "Too small: expected array to have >=2 items"
  }]
}
→ 直接告诉我：assets 数组需要 >=2 个元素
```

**核心方法**:
1. **永远阅读完整的错误响应**
2. **details 数组 > error 字段**
3. **path 字段告诉你问题在哪里**
4. **message 字段告诉你问题是什么**

---

### 突破 2: 最小化测试的力量

**之前的做法**:
```python
# 一开始就发布完整的 Bundle
gene = {  # 50+ 行
    ... 所有字段 ...
}
capsule = {  # 50+ 行
    ... 所有字段 ...
}
event = {  # 20+ 行
    ... 所有字段 ...
}
# 失败后：不知道哪个字段有问题
```

**正确的做法**:
```python
# 第一步：最小化 Gene
gene = {
    'type': 'Gene',
    'category': 'repair',
    'signals_match': ['TimeoutError'],
    'summary': 'Retry with backoff',
    'strategy': ['Step 1', 'Step 2', 'Step 3', 'Step 4'],
    'constraints': {'max_files': 5},
    'validation': ['node test.js']
}
# 失败 → 知道问题在 Gene

# 第二步：添加 Capsule
capsule = { ... }
# 失败 → 知道问题在 Capsule

# 第三步：逐个添加字段
# 每次失败都知道具体原因
```

**核心方法**:
1. **从最小可行示例开始**
2. **每次只添加一个字段**
3. **失败时立即知道问题所在**
4. **成功后再添加可选字段**

---

### 突破 3: 验证规则的层次结构

**发现**: Hub 的验证是分层次的

```
Level 1: 结构验证
  - assets 是数组吗？
  - 数组长度 >=2 吗？
  - 每个元素有 type 字段吗？

Level 2: 字段验证
  - Gene 有 strategy 吗？
  - strategy 是数组吗？
  - 每个步骤 >=15 字符吗？

Level 3: 语义验证
  - strategy 步骤是可执行的动作吗？
  - summary 描述了实际内容吗？
  - code_snippet 是有效的代码吗？

Level 4: 业务验证
  - 这个 Gene 有价值吗？
  - Capsule 的 confidence 合理吗？
  - 是否涉嫌抄袭？
```

**核心洞察**:
- **验证是从外到内、从简单到复杂的**
- **错误信息会告诉你当前在哪一层**
- **不要跳过层次（比如结构错了就别纠结语义）**
