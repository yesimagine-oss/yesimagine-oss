## 1️⃣ 事故定义与分级

### 事故定义

**事故**: 任何导致系统功能异常、性能下降、数据丢失或用户体验受损的事件。

### 分级标准

| 级别 | 定义 | 响应时间 | 通知方式 | 关闭条件 |
|------|------|---------|---------|---------|
| **P0** | 系统不可用/数据丢失 | 立即 | 飞书 + 邮件 | 修复 + 验证 +30 天无再发生 |
| **P1** | 功能降级/指标异常 | 24 小时 | 飞书 | 修复 + 验证 +7 天无再发生 |
| **P2** | 优化类问题 | 周度 | 日志记录 | 修复 + 验证 |
| **P3** | 建议类问题 | 月度 | 日志记录 | 评估后决定 |

### 事故示例

| 级别 | 示例 |
|------|------|
| **P0** | 网关宕机>1 小时、备份失败>3 天、Token 泄露、数据误删除 |
| **P1** | Lint 检查失败、健康分<75、Ingest 停滞>24h、Crontab 任务失败 |
| **P2** | 周报未生成、单领域知识<3 条、文档错别字、脚本警告 |
| **P3** | UI 优化建议、性能优化建议、新增功能建议 |

## 2️⃣ 事故记录标准

### 记录位置

```
/home/admin/.openclaw/workspace/.learnings/LRN-[TYPE]-YYYYMMDD-XXXXXX.md
```

### 文件命名规范

```
LRN-[TYPE]-YYYYMMDD-XXXXXX.md

TYPE 代码:
- SYS: 系统事故 (网关/Cron/备份)
- KB: 知识库事故 (Ingest/Lint/索引)
- SEC: 安全事故 (Token/权限/泄露)
- PERF: 性能事故 (超时/卡顿/资源)
- REPEAT: 重复事故 (同一问题再发生)
```

## 3️⃣ 复盘流程

### 复盘时机

| 级别 | 复盘时间 | 参与者 |
|------|---------|--------|
| **P0** | 修复后 24 小时内 | 全员 |
| **P1** | 修复后 3 天内 | 相关人员 |
| **P2** | 周度汇总复盘 | 维护者 |
| **P3** | 月度汇总评估 | 维护者 |

### 复盘检查清单

```
□ 事故现象描述清晰
□ 影响范围评估准确
□ 根因分析深入 (5 Why)
□ 改进措施具体可执行
□ 验证方法明确
□ 追踪周期合理
□ Gene 提炼判断正确
```

---

## 4️⃣ 改进验证

### 验证流程

```
改进措施执行 → 验证测试 → 记录结果 → 确认关闭
```

### 验证方法示例

| 改进措施 | 验证方法 |
|----------|---------|
| 修复脚本 Bug | 手动执行脚本 + 检查日志 |
| 增加监控告警 | 模拟故障 + 确认告警触发 |
| 更新 SOP 文档 | 按新 SOP 执行 + 确认有效 |
| 增加备份频率 | 检查备份目录 + 验证恢复 |

## 5️⃣ 效果追踪

### 追踪周期

| 级别 | 追踪周期 | 确认方式 |
|------|---------|---------|
| **P0** | 30 天 | 无再发生 + 监控指标正常 |
| **P1** | 7 天 | 无再发生 + 功能测试通过 |
| **P2** | 即时 | 修复后确认 |
| **P3** | 即时 | 评估后决定 |

### 再发生处理

**同一问题再发生:**
1. 升级事故级别 (P1→P0, P2→P1)
2. 重新复盘 (检查改进措施是否执行)
3. 记录为 `LRN-REPEAT-YYYYMMDD-XXXXXX`
4. 链接到原事故记录

## 6️⃣ Gene 提炼

### 提炼判断

| 条件 | 是否提炼 |
|------|---------|
| 系统性问题 (影响多个场景) | ✅ 提炼 |
| 重复发生问题 (≥2 次) | ✅ 提炼 |
| 单场景偶发问题 | ❌ 不提炼 |
| 配置类问题 (一次性修复) | ❌ 不提炼 |

### 提炼流程

```
事故复盘完成 → ⚠️用户确认 → Gene 草稿 → 标准验证 → 查重 → 入库
```

**用户确认问题:**
> 「此事故是否提炼为 Gene 入库？」
> - 是 → 自动生成 Gene 草稿
> - 否 → 仅保留事故记录

### 与采样前查重 SOP 衔接

Gene 提炼后，按 **采样前查重 SOP** 执行:
1. 查重检查 (Signals/Strategy 重叠度)
2. 合并判断 (>80% 重叠 → 合并)
3. 存入 `learnings/*.gene.md`
4. Git 提交归档
