## 1️⃣ 核心原则

**知识库优先 (Knowledge-First)**:
> 任何问题/任务，优先查询知识库，命中率约 80%

**三级查询流程**:
```
SOP → 事故记录 → 知识库 → 外部搜索
```

**Token 节省**:
- 查知识库：~100 tokens ($0.0001)
- 问大模型：~10,000 tokens ($0.01-0.10)
- **节省 100-1000 倍**

## 3️⃣ 三种标准场景

### 场景 1: SOP 覆盖场景 (命中率~40%)

**流程**:
```
1. 用户/系统发出指令
   ↓
2. Agent 识别问题类型
   ↓
3. 查询对应 SOP (learnings/*-sop.md)
   ↓
4. 按 SOP 流程执行
   ↓
5. 完成任务 + 记录日志
```

**示例**:
| 问题 | SOP | 执行结果 |
|------|-----|---------|
| 「如何备份？」 | cron-task-sop.md | 按 CRON-003 执行 |
| 「健康分多少？」 | health-monitoring-sop.md | 运行 health-alert.sh |
| 「Token 认证失败」 | accident-learning-sop.md | 查 LRN-AUTH-001 |

---

### 场景 2: 知识库有答案 (命中率~40%)

**流程**:
```
1. Agent 接收任务
   ↓
2. 查询知识库 (.learnings/ + wiki/)
   ↓
3. 找到答案/案例/Gene
   ↓
4. 综合当前情况调整
   ↓
5. 解决问题 + 更新记录
```

**示例**:
| 问题 | 知识库位置 | 答案 |
|------|-----------|------|
| 「Crontab 在哪？」 | cron-task-sop.md | `crontab -l` |
| 「Token 是什么？」 | openclaw.json (备份) | 见配置备份 |
| 「如何创建 Gene?」 | sampling-dedup-sop.md | 8 步流程 |

---

### 场景 3: 知识库无答案 (命中率~20%)

**流程**:
```
1. Agent 查询知识库
   ↓
2. 确认无答案
   ↓
3. 外部搜索 (官方文档/权威来源)
   ↓
4. 返回用户：「知识库无答案，建议参考：[官方链接]」
   ↓
5. 用户确认有价值 → 存入知识库
   ↓
6. Agent 读取新知识
   ↓
7. 解决问题 + 归档
```

**示例**:
| 问题 | 外部来源 | 知识库更新 |
|------|---------|-----------|
| 「OpenClaw 2026.4.15 新功能」 | docs.openclaw.ai | → wiki/openclaw-2026.4.15.md |
| 「EvoMap 最新政策」 | evomap.ai | → wiki/evomap-policy-2026.md |
| 「Ollama 0.5.0 变化」 | ollama.ai | → wiki/ollama-0.5.0.md |

## 5️⃣ 外部搜索规范

### 5.1 搜索优先级

| 优先级 | 来源 | 可信度 | 示例 |
|--------|------|--------|------|
| **P0** | 官方文档 | ✅ 100% | docs.openclaw.ai |
| **P1** | GitHub 仓库 | ✅ 95% | github.com/openclaw |
| **P2** | 权威社区 | ✅ 80% | Discord/论坛 |
| **P3** | 博客/教程 | ⚠️ 60% | 个人博客 |

### 5.2 入库标准

| 条件 | 是否入库 |
|------|---------|
| 官方文档/公告 | ✅ 必须入库 |
| 已验证的解决方案 | ✅ 必须入库 |
| 最佳实践/教程 | ✅ 推荐入库 |
| 未验证的信息 | ❌ 暂不入库 |

## 6️⃣ 用户补充知识库流程

### 6.1 用户提交

**位置**: `raw/` 目录

**格式**:
```markdown
# [标题]

**来源**: [URL]  
**采集时间**: YYYY-MM-DD  
**验证状态**: 待验证/已验证  
**标签**: #tag1 #tag2

---

[内容]
```

### 6.2 Agent 处理

**流程**:
```
1. 监控 raw/ 目录 (CRON-004 每日 04:00)
   ↓
2. 自动 Ingest (auto-ingest.py)
   ↓
3. 分类 + 打标
   ↓
4. 存入 wiki/ 对应目录
   ↓
5. 更新索引
   ↓
6. Git 提交
```
