## 二、RedAgentTeamllm-wiki 基本使用方法

### 2.1 基本使用概述

RedAgentTeamllm-wiki 是標準化知識管理系統，用於統一管理所有知識、報告、資產、規範等內容。

**核心目標:** 確保知識的規範性、完整性和可檢索性。

---

### 2.2 新知識入庫處理流程

當新知識（原始文件、報告、資產數據等）入庫時，必須嚴格遵循以下 3 步流程：

```
┌─────────────────────────────────────────────────────────┐
│  Step 1: Ingest 操作                                    │
├─────────────────────────────────────────────────────────┤
│  1. 將原始文件保存到 raw/（確保來源原始性和可追溯性）     │
│  2. 在 wiki/ 創建結構化頁面（簡化、梳理、規範化內容）    │
│  3. 按需添加交叉引用 [[page-name]]                      │
│  4. 更新 index.md（將新頁面加入索引）                    │
│  5. 更新 log.md（記錄 Ingest 時間、操作者、內容概述）     │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 2: Query 驗證                                      │
├─────────────────────────────────────────────────────────┤
│  1. 使用新知識核心關鍵詞執行 Query 操作                   │
│  2. 驗證新內容能否準確檢索                               │
│  3. 確認合成答案與原始內容一致（確保結構化處理正確）     │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 3: Lint 檢查                                       │
├─────────────────────────────────────────────────────────┤
│  1. 運行 Lint 檢查                                        │
│  2. 確認新內容無矛盾、非孤頁、無過時信息                 │
│  3. 如有問題立即修復，完成新知識存儲                     │
└─────────────────────────────────────────────────────────┘
```

---

### 2.3 更新方法

#### 內容更新

```
1. 更新 wiki/ 目錄中對應文件
2. 更新 log.md（記錄更新時間、內容、原因）
3. 如涉及重大變更，重新運行 Lint 檢查
```

#### 索引更新

```
每當新增、刪除或重命名頁面時：
→ 實時更新 index.md
→ 確保索引與 wiki/ 實際內容一致
→ 避免孤頁或無效索引條目
```

#### 模板更新

```
1. 將新模板保存到 schema/ 目錄
2. 舊模板添加 ".old" 後綴（保留歷史版本）
3. 更新 log.md（記錄更新詳情）
```

### 2.4 維護方法與週期（科學合理）

#### 每日維護（1 次/天，5-10 分鐘/次）

| 任務 | 說明 |
|------|------|
| 目錄檢查 | 確認當日新增/更新文件存儲在正確目錄 |

| Lint 簡查 | 簡要檢查當日 Lint 結果，及時處理明顯問題 |

#### 每週維護（1 次/週，30-60 分鐘/次）

| 任務 | 說明 |
|------|------|
| 完整 Lint 檢查 | 全面檢測矛盾、孤頁、過時內容、知識缺口 |
| raw/ 整理 | 刪除重複原始文件（保留最新版本） |
| 文件命名規範 | 統一格式：`日期 - 內容 - 類型.md` |
| index.md 檢查 | 檢查完整性與合理性，優化分類 |

#### 每月維護（1 次/月，1-2 小時/次）

| 任務 | 說明 |
|------|------|
| 系統驗證 | 檢查所有文件完整性、Schema 模板有效性、報告準確性 |
| 歷史歸檔 | 將 >3 個月未更新文件移至 `archive/` 子目錄 |
| 維護記錄回顧 | 總結日/週維護問題，分析根本原因 |
| 結構優化 | 根據實際使用頻率調整索引分類和目錄結構 |

### 2.5 問題修復方法

```
┌─────────────────────────────────────────────────────────┐
│  Step 1: 問題識別                                        │
├─────────────────────────────────────────────────────────┤
│  確認問題類型（文件丟失、內容錯誤、Lint 誤報、孤頁等）   │
│  確認影響範圍（單文件、多文件、全系統）                 │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 2: 問題定位                                        │

└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 3: 問題修復                                        │
├─────────────────────────────────────────────────────────┤
│  • 文件丟失：從最新備份恢復或從 raw/ 重新 Ingest         │
│  • 內容錯誤：修改 wiki/ 對應文件，更新 log.md，重跑 Lint │
│  • 孤頁：加入 index.md，驗證交叉引用                    │
│  • Lint 誤報：標記誤報關鍵詞，優化和規則，手動確認      │
│  • 目錄混亂：移動到正確目錄，更新 index.md              │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 4: 修復後驗證                                      │
├─────────────────────────────────────────────────────────┤
│  運行 Lint 檢查 + Query 驗證                             │
│  確認問題完全解決，無新問題引入                         │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  Step 5: 記錄與總結                                      │
├─────────────────────────────────────────────────────────┤
│  在 log.md 和 learnings/ 記錄問題、修復過程、結果        │
│  形成經驗，避免未來類似問題                             │
└─────────────────────────────────────────────────────────┘
```

## 三、RedAgentTeamllm-wiki 優缺點分析

### 3.1 優點

| 優點 | 說明 |
|------|------|
| **結構清晰** | 7 目錄職責明確，確保知識存儲規範化 |
| **工作流完整** | Ingest/Query/Lint 形成閉環，確保完整性、正確性、可檢索性 |
| **可追溯性強** | log.md 記錄所有操作，方便問題追溯和工作回顧 |
| **擴展性高** | 目錄結構可靈活調整，按需添加新子目錄 |
| **易於維護** | 科學維護週期和方法降低維護難度 |

---

### 3.2 缺點（重點討論）

#### 缺點 1: 自動化程度低 ⚠️

```
問題描述:
- 大多數操作（Ingest、索引更新、Lint 檢查、問題修復）需手動執行
- 耗時耗力，易導致人為錯誤（如演練中的報告誤放置）

影響:
- 工作效率低
- 錯誤率高
```

#### 缺點 2: Lint 檢查效率低 ⚠️

```
問題描述:
- 當前 Lint 檢查存在誤報
- 文件數量增加後檢查速度逐漸變慢（>200 文件時可能 >1 小時）

影響:
- 影響工作效率
- 可能延誤問題發現
```

#### 缺點 3: 大規模知識擴展性差 ⚠️

```
問題描述:
- 當前目錄結構適合 100-150 文件
- >200 文件時 index.md 變得臃腫，檢索速度下降，分類管理困難

影響:
- 限制系統長期發展
- 檢索效率降低
```

#### 缺點 4: 容錯率低 ⚠️

```
問題描述:
- 無自動備份機制
- 文件誤刪或錯誤修改後只能手動恢復（如有備份）

影響:
- 可能導致知識丟失
- 恢復成本高
```

#### 缺點 5: 交叉引用管理不便 ⚠️

```
問題描述:
- 當前使用 [[page-name]] 格式需手動添加
- 頁面名稱修改後交叉引用失效，難以批量查找修改

影響:
- 維護成本高
- 易產生無效引用
```

### 4.2 科學合理解決方案

#### 方案 1: 提升自動化程度（解決「自動化程度低」）

```
實施措施:
├── 自動 Ingest
│   └── 監控 raw/ 目錄，新增文件時自動執行 Ingest
│       （創建 wiki 頁面、更新 index.md 和 log.md）
├── 自動索引更新
│   └── wiki 頁面重命名/刪除時自動更新 index.md
│       並檢查交叉引用有效性
└── 自動 Lint 提醒
    ├── 每日自動運行簡化 Lint（重點檢測孤頁、誤放置）
    └── 每週末自動觸發完整 Lint，生成報告存儲到 reports/
```

**預期效果:** 減少 80% 手動操作，降低人為錯誤率

---

#### 方案 2: 優化 Lint 檢查（解決「Lint 檢查效率低」）

```
實施措施:
├── 優化 Lint 規則
│   └── 收集誤報關鍵詞，加入黑名單
│       消除關鍵詞相似導致的誤報
├── 增量 Lint 檢查
│   └── 僅檢查自上次檢查後新增/更新的文件
│       將檢查時間控制在 5 分鐘內
└── 優化 Lint 算法
    ├── 簡化非關鍵項檢查邏輯（如輕微格式問題）
    └── 重點檢查關鍵項（矛盾、孤頁、過時內容）
```

**預期效果:** 檢查時間從 60+ 分鐘降至 5-10 分鐘，誤報率降低 90%

---

#### 方案 3: 增強大規模知識擴展性（解決「擴展性差」）

├── 優化目錄結構
