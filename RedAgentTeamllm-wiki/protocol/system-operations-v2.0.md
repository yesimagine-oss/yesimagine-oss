### 1.2 內容篩選標準

**✅ 接收標準:**
- 與 EvoMap 資產發布直接相關
- 與 AI 知識變現直接相關
- 可操作、可執行、可驗證
- 有數據支持或實戰驗證

**❌ 拒絕標準:**
- 重複內容（已存在知識庫）
- 無實戰驗證的理論內容
- 過於籠統、無具體操作指引
- 與核心目標無關的冗余內容

## 二、每日更新要求

### 2.1 更新數量

| 指標 | 要求 | 說明 |
|------|------|------|
| **最低標準** | ≥30 條/天 | 必須完成 |
| **目標標準** | 30-50 條/天 | 推薦區間 |
| **內容聚焦** | 100% EvoMap + AI 變現 | 禁止冗余 |

### 2.2 內容分配建議

```
每日 30+ 條新知識分配:
├── EvoMap 資產發布標準/政策    8-10 條  (27-33%)
├── EvoMap 實戰經驗/錯誤/方案   10-12 條  (33-40%)
├── AI 知識變現模式/策略        6-8 條   (20-27%)
├── AI 知識變現案例/風險        4-6 條   (13-20%)
└── AgentTeamllm 系統優化       2-4 條   (7-13%)
```

### 2.3 Token 節省原則

**優先獲取內容:**
1. 核心信息（發布要求、政策變更）
2. 關鍵要點（變現核心方法、定價策略）
3. 錯誤預防（常見錯誤、避坑指南）
4. 實戰數據（成功案例、收入數據）

**避免內容:**
1. 冗長背景介紹
2. 重複說明
3. 無實質內容的過渡語句
4. 與核心目標無關的擴展

## 四、系統維護規範

### 4.1 每日維護（06:00 執行）

**檢查清單:**

```
□ 新知識更新數量 ≥30 條
□ 所有文件存儲在正確目錄
□ index.md 已更新（無孤頁）
□ log.md 已記錄當日操作
□ 系統健康狀況正常
□ 備份昨日完成
```

**異常處理:**
- 更新數量不足 → 立即補充
- 發現孤頁 → 立即加入索引
- 目錄錯誤 → 立即修正
- 備份失敗 → 手動執行並記錄

---

### 4.2 每週維護（週日 01:00 執行）

**檢查清單:**

```
□ 運行完整 Lint 檢查
□ 檢測矛盾內容
□ 檢測孤頁
□ 檢測過時內容
□ 檢測知識缺口
□ 生成 Lint 報告 (reports/)
□ 整理 raw/ 目錄（刪除重複）
□ 檢查 index.md 分類合理性
```

**報告要求:**
- 存儲位置：`reports/lint-weekly-YYYY-Www.md`
- 包含內容：問題列表、修復記錄、趨勢分析
- 發送通知：Feishu/郵件（如有配置）

---

### 4.3 每月維護（每月 1 日 02:00 執行）

**檢查清單:**

```
□ 全面系統驗證（文件完整性）
□ Schema 模板有效性檢查
□ 報告內容準確性覆核
□ 歸檔歷史數據（>3 個月未更新）
□ 回顧日/週維護記錄
□ 分析根本原因
□ 優化索引分類
□ 調整目錄結構（如需要）
```

**歸檔規則:**
- 歸檔目錄：`archive/YYYY-MM/`
- 歸檔條件：最後更新時間 >3 個月
- 保留索引：歸檔文件仍可在主索引中查詢

## 六、自動化功能配置

### 6.1 自動 Ingest

**觸發條件:** `raw/` 目錄新增文件

**執行流程:**
```
1. 監控 raw/ 目錄變化
2. 檢測到新文件 → 觸發 Ingest
3. 自動創建 wiki/ 結構化頁面
4. 自動更新 index.md
5. 自動更新 log.md
6. 自動添加交叉引用
7. 生成 Ingest 報告
```

**配置參數:**
- 監控間隔：30 秒
- 批處理大小：10 文件/批
- 錯誤重試：3 次
- 超時時間：60 秒

---

### 6.2 自動索引更新

**觸發條件:** wiki/ 頁面新增/刪除/重命名

**執行流程:**
```
1. 監控 wiki/ 目錄變化
2. 檢測到變化 → 觸發索引更新
3. 新增頁面 → 加入 index.md
4. 刪除頁面 → 移除 index.md 條目
5. 重命名頁面 → 更新條目 + 修復交叉引用
6. 驗證索引完整性
7. 記錄操作到 log.md
```

---

### 6.3 自動 Lint 檢查

**簡化版（每日 05:30）:**
- 檢測孤頁
- 檢測文件誤放置
- 檢測明顯矛盾

**完整版（每週日 01:00）:**
- 矛盾內容檢測
- 孤頁檢測
- 過時內容識別
- 知識缺口發現
- 交叉引用有效性檢查

**優化規則:**
- 誤報關鍵詞黑名單
- 增量檢查（僅檢查新增/更新文件）
- 優先級排序（P0 問題優先處理）

---

## 九、系統缺點消除

### 9.1 Lint 檢查優化

**問題:** 誤報、效率低

**解決方案:**
1. 建立誤報關鍵詞黑名單
2. 實施增量檢查（僅檢查變更文件）
3. 優化檢查算法（簡化非關鍵項）
4. 手動驗證確認機制

**目標:**
- 誤報率：<1%
- 檢查時間：<10 分鐘
- 準確率：>99%

---

### 9.2 目錄結構改進

**問題:** 大規模擴展性差

**解決方案:**
1. 增設子目錄（按內容類型）
2. 拆分索引文件（多級索引）
3. 添加分類標籤（快速篩選）

**目標:**
- 支持 500+ 文件
- 檢索速度提升 50%
- 單目錄文件數 <50

---

### 9.3 自動化功能完善

**問題:** 手動操作多、易出錯

**解決方案:**
1. 自動 Ingest（raw/ 監控）
2. 自動索引更新（wiki/ 監控）
3. 自動備份（每日 02:00）
4. 自動 Lint（每日簡化 + 每週完整）

**目標:**
- 自動化率：>80%

## 十、合規與審計

### 10.1 操作審計

所有系統操作必須記錄到 `log.md`:
- 操作時間
- 操作類型
- 操作者
- 操作內容概述
- 操作結果

### 10.2 變更管理

重大變更（目錄結構調整、索引拆分等）需要:
1. 變更前備份
2. 變更記錄
3. 變更後驗證
4. 變更報告

### 10.3 異常報告

系統異常（備份失敗、Ingest 錯誤、Lint 異常等）需要:
1. 立即記錄到 `accidents/`
2. 24 小時內修復
3. 修復後驗證
4. 經驗總結到 `learnings/`
