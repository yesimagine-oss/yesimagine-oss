## 🎯 目标

1. **统一命名** - 让文档名称自带分类和日期信息
2. **规范归档** - 防止根目录继续混乱
3. **提高查找效率** - 通过索引快速定位
4. **降低维护成本** - 清晰的文档生命周期管理

## 📋 命名规范

### 报告类文档

**格式**: `主题 - 类型 - 日期.md`

**示例:**
```
✅ pskoett-analysis-report-2026-03-22.md
✅ aliyun-assessment-report-2026-03-18.md
✅ skill-installation-status-2026-03-21.md

❌ report.md (无主题)
❌ pskoett.md (无类型)
❌ 2026-03-22-pskoett.md (日期位置错误)
```

**类型标识:**
| 类型 | 英文 | 说明 |
|------|------|------|
| 报告 | `report` | 正式报告 |
| 分析 | `analysis` | 深度分析 |
| 评估 | `assessment` | 能力/水平评估 |
| 状态 | `status` | 进度/状态更新 |
| 指南 | `guide` | 操作指南 |
| 计划 | `plan` | 学习/项目计划 |
| 总结 | `summary` | 阶段性总结 |
| 笔记 | `notes` | 学习笔记 |

### 学习笔记类

**格式**: `YYYY-MM-DD-主题.md`

**示例:**
```
✅ 2026-03-22-知识库优化笔记.md
✅ 2026-03-21-EvoMap 任务执行.md
✅ 2026-03-20-飞书 API 学习.md

❌ 笔记.md (无日期无主题)
❌ 2026-03-22.md (无主题)
```

### 索引类文档

**格式**: `INDEX.md` 或 `README.md`

**说明:**
- 每个知识库根目录必须有 `README.md` 或 `INDEX.md`
- 索引页必须包含：文档清单、快速入口、完成度

**示例:**
```
✅ evomap-knowledge-base/README.md
✅ nodejs-knowledge-base/README.md
✅ learning/KNOWLEDGE-INDEX.md
```

### 事故记录类

**格式**: `YYYY-MM-DD-事故主题.md`

**示例:**
```
✅ 2026-03-21-Control-UI-Token 事故.md
✅ 2026-03-20-链接交付事故.md
✅ 2026-03-17-飞书群组事故.md
```

## 📁 目录结构规范

### 标准知识库结构

```
knowledge-base-name/
├── README.md                 # 必需：索引页
├── 01-基础概念/
├── 02-环境配置/
├── 03-核心模块/
├── ...
└── archive/                  # 可选：归档目录
```

### 学习目录结构

```
learning/
├── KNOWLEDGE-INDEX.md        # 必需：总索引
├── 01-基础语法/
├── 02-进阶特性/
├── 03-标准库/
├── notes/                    # 学习笔记
├── archive/                  # 归档目录
└── [主题]-[类型]-[日期].md   # 独立报告
```

### 事故记录结构

```
.learnings/
├── LEARNINGS.md              # 必需：Learnings Log
├── YYYY-MM-DD-事故主题.md    # 事故记录
├── config/                   # 配置
└── daily/                    # 日常记录
```

### 项目目录结构

```
project-name/
├── README.md                 # 项目说明
├── docs/                     # 文档
├── scripts/                  # 脚本
├── logs/                     # 日志
└── archive/                  # 归档
```

## 🗂️ 归档规范

### 归档原则

| 条件 | 操作 | 说明 |
|------|------|------|
| 超过 7 天的临时文档 | 归档 | 防止根目录混乱 |
| 被新版替代的文档 | 归档 | 保留历史版本 |
| 项目结束的文档 | 归档到项目目录 | 统一管理 |
| 事故记录 | 永久保留 | 重要教训 |

### 归档目录结构

```
workspace/
├── archive/
│   ├── 2026-03/
│   │   ├── evolution-reports/     # 进化报告
│   │   ├── evomap-reports/        # EvoMap 报告
│   │   ├── feishu-reports/        # 飞书报告
│   │   └── accidents/             # 事故记录
│   └── 2026-02/
```

### 归档流程

```
1. 识别待归档文档
   ↓
2. 创建归档目录（如不存在）
   ↓
3. 移动文档到归档目录
   ↓
4. 更新索引页（标记已归档）
   ↓
5. 记录归档日志
```

### 归档示例

**根目录散落文档归档:**
```bash
# 进化报告
mv "2026-03-22 全方位进化总结.md" archive/2026-03/evolution-reports/
mv "2026-03-22 全方位进化报告.md" archive/2026-03/evolution-reports/

# EvoMap 报告
mv "EvoMap 價值與收益深度分析.md" archive/2026-03/evomap-reports/
mv "EvoMap 內容創作執行方案詳細版.md" archive/2026-03/evomap-reports/

# 飞书报告
mv "FEISHU-SECURITY-STRATEGY.md" archive/2026-03/feishu-reports/
mv "FEISHU-GROUP-GUIDE.md" archive/2026-03/feishu-reports/
```

## 📊 索引规范

### 索引页必备内容

每个知识库的 `README.md` 或 `INDEX.md` 必须包含：

1. **快速入口** - 3-5 个最常用文档链接
2. **文档清单** - 完整文档列表（表格形式）
3. **完成度** - 知识库完成百分比
4. **更新日志** - 最近更新时间
5. **负责人** - 维护者信息

### 索引页模板

```markdown
# 📚 [知识库名称]

**创建时间**: YYYY-MM-DD  
**最后更新**: YYYY-MM-DD  
**完成度**: XX%  
**文档总数**: X 个
```

## 🧹 清理规范

### 定期清理任务

**每日:**
- [ ] 检查根目录新增文档
- [ ] 临时文件及时删除

**每周日:**
- [ ] 归档散落文档
- [ ] 删除冗余文档
- [ ] 更新索引页
- [ ] 清理临时目录

**每月 1 日:**
- [ ] 全面文档健康检查
- [ ] 归档上月文档
- [ ] 更新文档统计
- [ ] 优化目录结构

### 冗余文档识别

**判断标准:**
- 内容重複度 >80%
- 同一主题的多个"最终版"
- 被新版完全替代的旧版

**处理方式:**
```
1. 保留最新版
2. 旧版移动到 archive/
3. 更新索引页标记
4. 记录清理日志
```
