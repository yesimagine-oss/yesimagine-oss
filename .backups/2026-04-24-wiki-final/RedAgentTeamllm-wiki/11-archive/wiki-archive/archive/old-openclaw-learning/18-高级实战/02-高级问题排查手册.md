## 🚨 紧急问题排查

### 问题 1: 服务完全无响应

#### 症状
```
- 消息不回复
- Web UI 无法访问
- SSH 连接正常
```

#### 排查步骤

```bash
# 1. 检查服务状态
systemctl status openclaw
openclaw status

# 2. 检查进程
ps aux | grep openclaw

# 3. 检查端口
netstat -tlnp | grep 18789
lsof -i :18789

# 4. 查看日志
openclaw logs --tail 100
journalctl -u openclaw -n 100

# 5. 检查资源
htop
df -h
free -h
```

#### 解决方案

```bash
# 方案 1: 重启服务
openclaw restart

# 方案 2: 强制重启
pkill -f openclaw
openclaw start

# 方案 3: 清理后重启
rm -rf ~/.openclaw/cache/*
openclaw restart

# 方案 4: 重新安装
openclaw update --force
```

### 问题 2: API 调用全部失败

#### 症状
```
- 所有对话返回错误
- 日志显示 401/403/500 错误
- 模型切换无效
```

#### 排查步骤

```bash
# 1. 检查 API Key
openclaw config | grep apiKey

# 2. 测试 API 连通性
curl -v -H "Authorization: Bearer sk-YOUR_KEY" \
  https://coding.dashscope.aliyuncs.com/v1/models

# 3. 检查余额
# 登录百炼控制台查看

# 4. 检查网络
ping coding.dashscope.aliyuncs.com
curl -I https://coding.dashscope.aliyuncs.com
```

#### 解决方案

```bash
# 方案 1: 更新 API Key
openclaw dashboard
# 重新填入正确的 Key

# 方案 2: 清除配置缓存
rm ~/.openclaw/agents/main/agent/models.json
openclaw restart

# 方案 3: 切换备用模型
openclaw models default glm-4.7

# 方案 4: 检查订阅状态
# 登录百炼控制台确认订阅有效
```

### 问题 3: 内存泄漏

#### 症状
```
- 内存使用持续增长
- 服务运行几天后崩溃
- 重启后恢复正常
```

#### 排查步骤

```bash
# 1. 监控内存趋势
watch -n 5 'ps aux | grep openclaw | grep -v grep | awk "{print $4}"'

# 2. 检查 Node.js 堆内存
node --inspect openclaw

# 3. 生成堆快照
# 使用 Chrome DevTools 连接

# 4. 检查会话数量
ls -la ~/.openclaw/sessions/ | wc -l
```

#### 解决方案

```bash
# 方案 1: 设置内存限制
export NODE_OPTIONS="--max-old-space-size=512"

# 方案 2: 使用 PM2 自动重启
pm2 start openclaw --memory-restart 500M

# 方案 3: 定期清理会话
# 添加定时任务清理 30 天前的会话

# 方案 4: 更新到最新版本
openclaw update
```

## 🛠️ 诊断工具集

### 1. 健康检查脚本

```bash
#!/bin/bash
# ~/scripts/health-check.sh

echo "=== OpenClaw 健康检查 ==="
echo ""

# 服务状态
echo "1. 服务状态"
if systemctl is-active --quiet openclaw; then
  echo "   ✅ 服务运行中"
else
  echo "   ❌ 服务未运行"
fi

# 端口检查
echo ""
echo "2. 端口检查"
if netstat -tlnp | grep -q 18789; then
  echo "   ✅ 端口 18789 已监听"
else
  echo "   ❌ 端口 18789 未监听"
fi

# API 检查
echo ""
echo "3. API 检查"
RESPONSE=$(curl -s -o /dev/null -w "%{http_code}" \
  -H "Authorization: Bearer sk-YOUR_KEY" \
  https://coding.dashscope.aliyuncs.com/v1/models)
if [ "$RESPONSE" = "200" ]; then
  echo "   ✅ API 正常"
else
  echo "   ❌ API 异常 (HTTP $RESPONSE)"
fi

# 资源检查
echo ""
echo "4. 资源检查"
CPU=$(ps aux | grep openclaw | grep -v grep | awk '{print $3}')
MEM=$(ps aux | grep openclaw | grep -v grep | awk '{print $4}')
echo "   CPU: ${CPU}%"
echo "   内存：${MEM}%"

# 磁盘检查
echo ""
echo "5. 磁盘检查"
DISK=$(df -h / | tail -1 | awk '{print $5}')
echo "   磁盘使用：$DISK"

echo ""
echo "=== 检查完成 ==="
```

### 2. 日志分析脚本

```bash
#!/bin/bash
# ~/scripts/log-analyzer.sh

LOG_FILE=~/.openclaw/logs/openclaw.log

echo "=== 日志分析 ==="
echo ""

# 错误统计
echo "1. 错误统计 (最近 24 小时)"
grep "ERROR" $LOG_FILE | \
  since "24 hours ago" | \
  wc -l | xargs echo "   错误数:"

# 常见错误
echo ""
echo "2. 常见错误 TOP 5"
grep "ERROR" $LOG_FILE | \
  awk -F': ' '{print $2}' | \
  sort | uniq -c | sort -rn | head -5

# API 调用统计
echo ""
echo "3. API 调用统计"
grep "api" $LOG_FILE | wc -l | xargs echo "   调用次数:"

# 慢查询
echo ""
echo "4. 慢查询 (>5 秒)"
grep "timeout\|slow" $LOG_FILE | tail -10

echo ""
echo "=== 分析完成 ==="
```
