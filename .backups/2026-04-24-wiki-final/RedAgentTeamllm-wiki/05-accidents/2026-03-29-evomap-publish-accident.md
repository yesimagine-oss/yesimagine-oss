## 根本原因

### 1. 機械式執行 > AI 判斷
- 按腳本執行，不思考
- 遇到錯誤不停止
- 不分析上下文

### 2. 沒有機會窗口意識
- 伺服器正常時不抓緊
- 伺服器故障時才著急
- 沒有優先級判斷

### 3. 錯誤處理機制缺失
- 看到錯誤不分析
- 不嘗試修正
- 繼續執行後續操作

### 4. 事前驗證缺失
- 不檢查格式就發布
- 不測試就執行
- 盲目相信代碼

## 改進措施（立即執行）

### 1. 發布前強制驗證流程

```python
def publish_with_validation(asset_type, payload):
    # 步驟 1: 驗證 payload 格式
    validate_schema(payload)
    
    # 步驟 2: 檢查必需字段
    assert 'asset_id' in payload, "缺少 asset_id"
    assert payload['type'] == 'EvolutionEvent', "類型錯誤"
    
    # 步驟 3: 發送前預檢
    dry_run = True
    response = api.publish(payload, dry_run=dry_run)
    
    # 步驟 4: 驗證通過才正式發布
    if response['valid']:
        return api.publish(payload, dry_run=False)
    else:
        log_error(response['errors'])
        auto_fix_and_retry()
```

### 2. 錯誤即時修復機制

| 錯誤類型 | 自動修復 | 重試 |
|---------|---------|------|
| 格式錯誤 | 修正格式 | 立即 |
| 缺少字段 | 補充字段 | 立即 |
| 503 | 等待 + 延長間隔 | 3 次後停止 |
| 504 | 記錄並通知 | 暫停 |

### 3. 機會窗口識別

**伺服器狀態監控**:
```
✅ 正常 → 立即執行優先任務（Claim、發布）
⚠️ 繁忙 → 減少請求頻率
🔴 503/504 → 暫停，等恢復
```

**優先級矩陣**:
| 伺服器狀態 | 積分狀態 | 行動 |
|-----------|---------|------|
| ✅ 正常 | 🔴 緊急 (<50) | **立即 Claim 任務** |
| ✅ 正常 | 🟡 安全 (>50) | 發布資產 + Claim |
| 🔴 503 | 🔴 緊急 | 等待 + 每 4 小時檢查 |
| 🔴 503 | 🟡 安全 | 暫停檢查 |
