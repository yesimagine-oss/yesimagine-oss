## 🚨 问题分类与排查

### 类别 1: 服务无法启动

#### 症状
```bash
openclaw start
# 无响应或直接退出
```

#### 排查步骤

```bash
# 1. 检查 Node.js 版本
node -v
# 需要 v22+

# 2. 检查端口占用
lsof -i :3000
netstat -tlnp | grep 3000

# 3. 查看详细错误
openclaw start --verbose

# 4. 检查配置文件
openclaw config --validate

# 5. 查看完整日志
cat ~/.openclaw/logs/openclaw.log | tail -100
```

#### 常见原因与解决

| 原因 | 错误信息 | 解决方案 |
|------|----------|----------|
| 端口占用 | `EADDRINUSE` | `kill $(lsof -t -i:3000)` |
| 配置错误 | `JSON parse error` | 修复配置文件语法 |
| 权限不足 | `EACCES` | `chmod 755 ~/.openclaw` |
| Node 版本 | `requires Node v22` | `nvm install 22` |

### 类别 2: 模型调用失败

#### 症状
```
API request failed
或
长时间无响应后超时
```

#### 排查步骤

```bash
# 1. 检查 API Key 配置
openclaw config | grep -A 5 bailian

# 2. 测试 API 连通性
curl -v -H "Authorization: Bearer sk-YOUR_KEY" \
  https://coding.dashscope.aliyuncs.com/v1/models

# 3. 检查网络延迟
ping coding.dashscope.aliyuncs.com
mtr coding.dashscope.aliyuncs.com

# 4. 查看模型日志
openclaw logs --grep "model" --tail 50

# 5. 检查余额/用量
# 登录百炼控制台查看
```

#### 常见错误码

| 错误码 | 含义 | 解决方案 |
|--------|------|----------|
| 401 | 认证失败 | 检查 API Key |
| 403 | 权限不足 | 检查 Key 权限 |
| 429 | 请求过多 | 降低频率或升级 |
| 500 | 服务器错误 | 稍后重试 |
| 503 | 服务不可用 | 检查服务状态 |

### 类别 3: 技能无法加载

#### 症状
```
Skill not found: xxx
或
技能启用但无响应
```

#### 排查步骤

```bash
# 1. 列出已安装技能
openclaw skills list

# 2. 检查技能文件
ls -la ~/.openclaw/workspace/skills/

# 3. 查看技能详情
openclaw skills show <skill-name>

# 4. 检查技能依赖
cat ~/.openclaw/workspace/skills/<name>/package.json

# 5. 重新安装技能
openclaw skills uninstall <name>
openclaw skills install <name>

# 6. 查看技能加载日志
openclaw logs --grep "skill" --tail 50
```

#### 技能文件结构检查

```bash
# 检查必需文件
cd ~/.openclaw/workspace/skills/<skill-name>
ls -la

# 应该有:
# - SKILL.md (必需)
# - index.js 或 index.ts (必需)
# - package.json (推荐)
```

### 类别 4: 通道消息不发送

#### 症状
- Telegram/Discord 收不到消息
- 消息显示发送但实际未送达

#### 排查步骤

```bash
# 1. 检查通道状态
openclaw channels list

# 2. 检查通道配置
openclaw config | grep -A 10 "channels"

# 3. 测试通道连接
# Telegram: 发送消息给 bot 看是否响应
# Discord: 在频道中 @bot 看是否响应

# 4. 查看通道日志
openclaw logs --grep "telegram\|discord" --tail 50

# 5. 检查 Bot 状态
# Telegram: https://api.telegram.org/bot<TOKEN>/getMe
# Discord: 检查开发者后台
```

#### Telegram 专项排查

```bash
# 测试 Bot API
curl https://api.telegram.org/bot<TOKEN>/getMe

# 检查 Webhook（如使用）
curl https://api.telegram.org/bot<TOKEN>/getWebhookInfo

# 获取更新
curl https://api.telegram.org/bot<TOKEN>/getUpdates
```

#### Discord 专项排查

```bash
# 检查 Bot 权限
# 1. 服务器设置 → 角色
# 2. 确保 Bot 角色有发送消息权限

# 检查 Intents
# 开发者后台 → Bot → Privileged Gateway Intents
# 确保开启必要 Intents
```

### 类别 5: 定时任务不执行

#### 症状
- 到时间没有收到提醒
- cron 任务似乎没运行

#### 排查步骤

```bash
# 1. 检查 cron 配置
openclaw config | grep -A 20 "crons"

# 2. 验证 cron 表达式
# 使用 https://crontab.guru 验证

# 3. 查看 cron 日志
openclaw logs --grep "cron" --tail 100

# 4. 检查系统时间
date
timedatectl

# 5. 手动触发测试
openclaw chat "执行 cron 命令内容"

# 6. 检查时区设置
cat /etc/timezone
```

#### Cron 表达式验证

```bash
# 常用表达式参考
"0 7 * * *"    # 每天 7 点
"*/30 * * * *" # 每 30 分钟
"0 9 * * 1-5"  # 工作日 9 点
"0 0 1 * *"    # 每月 1 号

# 验证工具
npm install -g cron-validator
cron-validator "0 7 * * *"
```

### 类别 6: 性能问题

#### 症状
- 响应缓慢
- 内存占用高
- CPU 使用率高

#### 排查步骤

```bash
# 1. 检查系统资源
htop
free -h
df -h

# 2. 检查进程状态
ps aux | grep openclaw

# 3. 查看性能日志
openclaw logs --grep "slow\|timeout" --tail 50

# 4. 检查模型响应时间
time openclaw chat "test"

# 5. 监控资源趋势
watch -n 5 'free -h && echo && df -h /'
```

#### 性能优化措施

```bash
# 1. 增加 Swap（如内存不足）
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 2. 清理缓存
openclaw clean --cache

# 3. 减少并发技能
# 编辑配置，禁用不常用技能

# 4. 优化日志级别
# 编辑配置，设置 logging.level = "warn"
```

### 类别 7: 数据丢失

#### 症状
- 记忆/会话数据丢失
- 配置文件消失

#### 排查步骤

```bash
# 1. 检查工作区目录
ls -la ~/.openclaw/workspace/

# 2. 检查文件权限
stat ~/.openclaw/workspace/MEMORY.md

# 3. 查看磁盘错误
dmesg | grep -i error

# 4. 检查备份
ls -la ~/.openclaw/backups/

# 5. 恢复备份
openclaw config --import backup.json
```

#### 数据恢复

```bash
# 1. 从备份恢复
cp ~/.openclaw/backups/latest/* ~/.openclaw/workspace/

# 2. 从 Git 恢复（如有）
cd ~/.openclaw/workspace
git checkout .

# 3. 手动重建
# 根据文档重新创建配置文件
```
