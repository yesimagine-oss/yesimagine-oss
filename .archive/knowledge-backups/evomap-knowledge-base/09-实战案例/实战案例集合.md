## 案例 1: React 性能优化

### 背景

**问题:** 电商网站列表页面滚动卡顿

**症状:**
- 1000+ 商品列表
- 滚动帧率 < 30fps
- 内存占用 > 500MB

### 分析过程

**步骤 1: 性能分析**
```javascript
// 使用 React DevTools Profiler
<Profiler id="ProductList" onRender={onRenderCallback}>
  <ProductList products={products} />
</Profiler>

function onRenderCallback(id, phase, actualDuration) {
  console.log(`${id} 渲染耗时：${actualDuration}ms`);
}
```

**步骤 2: 识别问题**
- ❌ 所有 1000+ 商品同时渲染
- ❌ 每次滚动都重新渲染所有组件
- ❌ 图片未懒加载

### 解决方案

**Gene (策略):**
```json
{
  "type": "Gene",
  "id": "gene_react_list_optimization",
  "category": "optimize",
  "summary": "React 长列表优化使用虚拟滚动 + 懒加载。只渲染可见区域项目，配合 React.memo 避免不必要重渲染。",
  "signals_match": [
    "react_performance",
    "virtual_scroll",
    "lazy_loading",
    "React 性能优化",
    "虚拟滚动"
  ],
  "strategy": [
    "安装 react-window 实现虚拟滚动",
    "使用 React.memo 包裹列表项组件",
    "实现图片懒加载",
    "使用 useMemo 缓存过滤逻辑"
  ]
}
```

**Capsule (实现):**
```javascript
// 方案 1: 使用 react-window
import { FixedSizeList } from 'react-window';

function ProductList({ products }) {
  const Row = ({ index, style }) => (
    <div style={style}>
      <ProductItem product={products[index]} />
    </div>
  );

  return (
    <FixedSizeList
      height={600}
      itemCount={products.length}
      itemSize={100}
      width="100%"
    >
      {Row}
    </FixedSizeList>
  );
}

// 方案 2: React.memo + useMemo
const ProductItem = React.memo(({ product }) => {
  return (
    <div>
      <img loading="lazy" src={product.image} />
      <h3>{product.name}</h3>
    </div>
  );
});

function ProductList({ products, filter }) {
  const filteredProducts = useMemo(() => {
    return products.filter(p => p.category === filter);
  }, [products, filter]);

  return (
    <div>
      {filteredProducts.map(p => (
        <ProductItem key={p.id} product={p} />
      ))}
    </div>
  );
}
```

### 效果验证

**优化前后对比:**

| 指标 | 优化前 | 优化后 | 改善 |
|------|--------|--------|------|
| 初始渲染 | 2000ms | 200ms | 90% ↓ |
| 滚动帧率 | 25fps | 60fps | 140% ↑ |
| 内存占用 | 520MB | 150MB | 70% ↓ |
| DOM 节点 | 1000+ | 10-15 | 98% ↓ |

### 经验教训

**✅ 成功因素:**
- 虚拟滚动是长列表优化首选
- React.memo 避免子组件不必要渲染
- 图片懒加载减少初始负载

**⚠️ 注意事项:**
- 虚拟滚动需要固定高度
- key 必须稳定且唯一
- 避免在渲染函数中创建对象

## 案例 2: 数据库查询优化

### 背景

**问题:** 订单查询接口响应慢

**症状:**
- 平均响应时间 > 3 秒
- 数据库 CPU 持续 80%+
- 慢查询日志频繁

### 分析过程

**步骤 1: 慢查询分析**
```sql
-- 原始查询
SELECT * FROM orders o
JOIN users u ON o.user_id = u.id
JOIN order_items oi ON o.id = oi.order_id
WHERE o.created_at > '2026-01-01'
ORDER BY o.created_at DESC;
```

**步骤 2: EXPLAIN 分析**

**Capsule (实现):**
```sql
-- 方案 1: 添加索引
CREATE INDEX idx_orders_created_at ON orders(created_at DESC);
CREATE INDEX idx_orders_user_id ON orders(user_id);

-- 方案 2: 优化查询
SELECT 
  o.id, o.total_amount, o.status, o.created_at,
  u.name as user_name
FROM orders o
JOIN users u ON o.user_id = u.id
WHERE o.created_at > '2026-01-01'
ORDER BY o.created_at DESC
LIMIT 20 OFFSET 0;

-- 方案 3: 使用覆盖索引
CREATE INDEX idx_orders_covering 
ON orders(created_at DESC, user_id, total_amount, status);
```

| 数据库 CPU | 80% | 15% | 81% ↓ |

**✅ 成功因素:**

**问题:** API 被恶意调用导致服务不可用

**症状:**
- 某 IP 每秒请求 1000+ 次

**Capsule (实现):**
```javascript
// 基于 Redis 的令牌桶限流
const Redis = require('ioredis');
const redis = new Redis();

class RateLimiter {
  constructor(key, maxRequests, windowMs) {
    this.key = `rate_limit:${key}`;
    this.maxRequests = maxRequests;
    this.windowMs = windowMs;
  }

  async isAllowed() {
    const now = Date.now();
    const windowKey = `${this.key}:${Math.floor(now / this.windowMs)}`;
    
    const current = await redis.incr(windowKey);
    if (current === 1) {
      await redis.pexpire(windowKey, this.windowMs);
    }
    
    return current <= this.maxRequests;
  }

  async getRemaining() {
    const now = Date.now();
    const windowKey = `${this.key}:${Math.floor(now / this.windowMs)}`;
    const current = await redis.get(windowKey) || 0;
    return Math.max(0, this.maxRequests - current);
  }
}

// Express 中间件
async function rateLimitMiddleware(req, res, next) {
  const ip = req.ip;
  const limiter = new RateLimiter(ip, 100, 60000); // 100 次/分钟
  
  const allowed = await limiter.isAllowed();
  const remaining = await limiter.getRemaining();
  
  res.set('X-RateLimit-Remaining', remaining);
  
  if (!allowed) {
    return res.status(429).json({
      error: 'Too Many Requests',
      retryAfter: 60
    });
  }
  
  next();
}
```

| 恶意请求 | ❌ 无限制 | ✅ 被限制 |
| 服务器负载 | 95% | 30% |

## 案例 4: Docker 构建优化

### 背景

**问题:** Docker 镜像构建慢，体积大

**症状:**
- 构建时间 > 10 分钟
- 镜像体积 > 1GB
- CI/CD 流水线超时

### 解决方案

**优化前:**
```dockerfile
FROM node:18
WORKDIR /app
COPY . .
RUN npm install
RUN npm run build
CMD ["node", "dist/index.js"]
```

**优化后:**
```dockerfile
# 多阶段构建
FROM node:18-alpine AS builder
WORKDIR /app

# 利用 Docker 层缓存
COPY package*.json ./
RUN npm ci --only=production

COPY . .
RUN npm run build

# 生产镜像
FROM node:18-alpine
WORKDIR /app

# 只复制必要文件
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/dist ./dist

# 使用非 root 用户
RUN addgroup -g 1001 -S nodejs
RUN adduser -S nodejs -u 1001
USER nodejs

CMD ["node", "dist/index.js"]
```

### 效果验证

| 指标 | 优化前 | 优化后 | 改善 |
|------|--------|--------|------|
| 构建时间 | 12 分钟 | 3 分钟 | 75% ↓ |
| 镜像体积 | 1.2GB | 150MB | 87% ↓ |
| 推送时间 | 5 分钟 | 1 分钟 | 80% ↓ |
| 启动时间 | 10 秒 | 2 秒 | 80% ↓ |
