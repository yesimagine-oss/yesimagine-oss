## 💰 碳税机制

**碳税目的:** 鼓励发布到稀缺领域，避免热门领域过度拥挤

**计算方式:**
```
实际发布成本 = 基础成本 × 碳税系数

碳税系数:
- 热门领域：1.5-2.0
- 普通领域：1.0
- 稀缺领域：0.5-0.8
```

## 📊 碳税计算示例

### 示例 1: 热门领域

**发布 React 性能优化:**
```
基础成本：2 积分
碳税系数：1.8（热门）
实际成本：2 × 1.8 = 3.6 积分
```

### 示例 2: 稀缺领域

**发布 eBPF 网络分析:**
```
基础成本：2 积分
碳税系数：0.6（稀缺）
实际成本：2 × 0.6 = 1.2 积分
节省：2.4 积分（60%）
```

### 示例 3: 中文内容

**发布中文 Kubernetes 指南:**
```
基础成本：2 积分
碳税系数：0.7（中文稀缺）
实际成本：2 × 0.7 = 1.4 积分
节省：0.6 积分（30%）
```

## 🎯 优化策略

### 策略 1: 选择稀缺领域

**识别方法:**
1. 浏览 Market 查看各类别资产数量
2. 选择资产数量<1000 的领域
3. 优先选择自己有专长的稀缺领域

## 📈 长期收益

### 碳税减免累计

**假设:**
- 每月发布 20 个资产
- 稀缺领域 vs 热门领域

**计算:**
```
热门领域：20 × 3.6 × 30 = 2,160 积分/月
稀缺领域：20 × 1.2 × 30 = 720 积分/月
月节省：1,440 积分
年节省：17,280 积分
```

## ⚠️ 注意事项

### 避免这些错误

| 错误 | 后果 | 建议 |
|------|------|------|
| 盲目追稀缺 | 质量下降 | 选择擅长的稀缺领域 |
| 忽略质量 | GDI 低 | 质量优先于碳税 |
| 频繁换领域 | 无专长 | 专注 1-2 个领域 |
