## Day 2 - 2026-03-18：控制台高級操作

### 1. 快照管理

#### 1.1 手動快照

**創建步驟:**
```
1. 實例詳情頁 → 快照 → 創建快照
2. 選擇磁盤（系統盤/數據盤）
3. 填寫快照名稱和備註
4. 確認創建
5. 等待完成（約 5-10 分鐘）
```

**建議創建快照的時機:**
- ✅ 系統更新前
- ✅ 應用部署前
- ✅ 配置變更前
- ✅ 定期備份（每週/每月）

**快照信息:**
```yaml
快照 ID: s-xxxxxxxxx
快照名稱：自定義
磁盤 ID: d-xxxxxxxxx
創建時間：2026-03-18 05:50
狀態：完成/創建中
進度：100%
來源磁盤：40GB 系統盤
```

#### 1.2 自動快照策略

**設置步驟:**
```
1. 磁盤詳情頁 → 自動快照策略
2. 創建策略
3. 配置參數：
   - 策略名稱：daily-backup
   - 執行時間：02:00（業務低峰期）
   - 重複日期：每天 / 每週一、三、五
   - 保留天數：7 天 / 30 天
4. 應用到磁盤
5. 確認應用
```

**最佳實踐:**
```yaml
日常備份:
  執行時間：02:00
  重複日期：每天
  保留天數：7 天
  適用：生產環境

週期備份:
  執行時間：03:00
  重複日期：每週日
  保留天數：30 天
  適用：開發環境

關鍵節點備份:
  執行時間：變更前後
  保留天數：90 天
  適用：重大變更
```

#### 1.3 快照費用

| 類型 | 計費方式 | 說明 |
|------|---------|------|
| **手動快照** | 按存儲容量 | 0.12 元/GB/月（參考） |
| **自動快照** | 按存儲容量 | 同手動快照 |
| **保留期內** | 部分免費 | 部分套餐包含免費額度 |

**費用計算示例:**
```
40GB 系統盤快照 × 7 天保留
= 40GB × 0.12 元/GB/月 ÷ 30 天 × 7 天
≈ 0.11 元/週

建議：定期清理舊快照，控制成本
```

#### 1.4 使用快照還原

**還原場景:**
- 系統故障恢復
- 誤刪除文件恢復
- 回滾到之前的狀態

**還原步驟:**
```
1. 停止實例（必須）
2. 快照詳情頁 → 創建磁盤
3. 選擇原實例
4. 確認還原（會覆蓋現有數據）
5. 啟動實例
```

**注意事項:**
- ⚠️ 還原會清空磁盤當前數據
- ⚠️ 還原前建議創建當前狀態快照
- ⚠️ 實例必須處於停止狀態

### 2. 自定義鏡像

#### 2.1 從實例創建鏡像

**適用場景:**
- 標準化環境覆制
- 批量部署相同配置
- 環境模板保存
- 分享給其他賬號

**創建步驟:**
```
1. 實例詳情頁 → 創建自定義鏡像
2. 選擇系統盤
3. 填寫鏡像信息：
   - 鏡像名稱：my-ubuntu-nginx
   - 描述：預裝 Nginx 的 Ubuntu 22.04
4. 確認創建
5. 等待完成（約 10-20 分鐘）
```

**鏡像信息:**
```yaml
鏡像 ID: m-xxxxxxxxx
鏡像名稱：自定義
操作系統：Ubuntu 22.04
鏡像大小：5GB
創建時間：2026-03-18
狀態：可用/創建中
來源實例：swas-xxxxxxxxx
```

#### 2.2 使用自定義鏡像

**創建新實例時使用:**
```
1. 創建實例 → 選擇系統鏡像
2. 切換到「自定義鏡像」標籤
3. 選擇已創建的鏡像
4. 繼續完成實例創建
```

**更換系統時使用:**
```
1. 實例詳情頁 → 更換系統
2. 選擇「自定義鏡像」
3. 選擇鏡像
4. 確認更換（數據會丟失！）
```

**注意事項:**
- ⚠️ 更換系統會清空系統盤
- ⚠️ 提前創建快照備份
- ⚠️ 公網 IP 保持不變

#### 2.3 鏡像分享

**分享給其他阿里雲賬號:**
```
1. 鏡像詳情頁 → 共享鏡像
2. 添加共享賬號（阿里雲賬號 ID）
3. 確認共享
4. 對方在創建實例時可見
```

**取消共享:**
```
1. 鏡像詳情頁 → 共享鏡像
2. 移除共享賬號
3. 確認移除
```

### 3. 數據盤管理

#### 3.1 添加數據盤

**適用場景:**
- 系統盤空間不足
- 數據與系統分離
- 需要更大存儲空間

**購買步驟:**
```
1. 實例詳情頁 → 磁盤 → 添加磁盤
2. 選擇配置：
   - 容量：20GB - 2TB
   - 類型：SSD / 高效雲盤
   - 付費方式：包月/包年
3. 確認訂單並支付
4. 等待創建完成
```

**磁盤類型對比:**

| 類型 | 性能 | 價格 | 適用場景 |
|------|------|------|---------|
| **SSD** | 高 IOPS，低延遲 | 較高 | 數據庫、高 IO 應用 |
| **高效雲盤** | 中等性能 | 經濟 | 一般應用、日誌存儲 |

#### 3.2 格式化與掛載

**查看新磁盤:**
```bash
# 列出所有磁盤
lsblk

# 輸出示例：
# NAME   MAJ:MIN RM SIZE RO TYPE MOUNTPOINT
# vda    253:0    0  40G  0 disk 
# └─vda1 253:1    0  40G  0 part /
# vdb    253:16   0 100G  0 disk  # ← 新磁盤
```

**格式化磁盤:**
```bash
# 格式化為 ext4（假設新磁盤為 /dev/vdb）
mkfs.ext4 /dev/vdb

# 或格式化為 xfs
mkfs.xfs /dev/vdb
```

**創建掛載點並掛載:**
```bash
# 創建掛載點
mkdir /data

# 掛載磁盤
mount /dev/vdb /data

# 驗證掛載
df -h

# 設置權限
chown www-data:www-data /data
chmod 755 /data
```

**開機自動掛載:**
```bash
# 獲取磁盤 UUID
blkid /dev/vdb

# 編輯 fstab
vim /etc/fstab

# 添加一行（使用 UUID 更穩定）：
# UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /data ext4 defaults 0 0
# 或使用設備名：
# /dev/vdb /data ext4 defaults 0 0

# 測試 fstab 配置
mount -a
```

#### 3.3 數據盤擴容

**擴容步驟:**
```
1. 控制台 → 磁盤詳情頁 → 升級配置
2. 選擇新容量
3. 支付差價
4. 等待完成
```

**擴展文件系統:**
```bash
# 查看磁盤新容量
lsblk

# 擴展文件系統（ext4）
resize2fs /dev/vdb

# 擴展文件系統（xfs）
xfs_growfs /data

# 驗證
df -h
```

### 4. 負載均衡（簡介）

#### 4.1 什麼是負載均衡

**作用:**
- 將流量分發到多台服務器
- 提高可用性
- 水平擴展能力

**阿里雲產品:**
- **SLB** (Server Load Balancer) - 傳統負載均衡
- **ALB** (Application Load Balancer) - 應用層負載均衡
- **NLB** (Network Load Balancer) - 網絡層負載均衡
- **輕量應用服務器** - 自帶簡單負載均衡功能

#### 4.2 輕量服務器的負載均衡

**適用場景:**
- 小型網站
- 開發測試環境
- 個人項目

**配置方式:**
```
1. 控制台 → 負載均衡
2. 創建實例
3. 添加後端服務器
4. 配置轉發規則
5. 綁定公網 IP
```

### 5. 自動擴容（簡介）

#### 5.1 彈性伸縮（Auto Scaling）

**核心概念:**
- **伸縮組**: 具有相似應用的實例集合
- **伸縮配置**: 實例配置模板
- **伸縮規則**: 觸發擴容/縮容的條件
- **告警任務**: 基於監控指標觸發

**伸縮場景:**
```yaml
定時伸縮:
  場景：工作日白天流量高
  配置：工作日 9:00 擴容，18:00 縮容

告警伸縮:
  場景：流量突發
  配置：CPU > 80% 擴容，CPU < 30% 縮容

固定伸縮:
  場景：保持固定數量
  配置：始終保持 2 台實例
```

#### 5.2 配置步驟（簡化版）

```
1. 訪問：https://ess.console.aliyun.com/
2. 創建伸縮組
3. 配置伸縮組屬性：
   - 地域
   - 網絡類型
   - 最小/最大實例數
4. 創建伸縮配置
5. 啟用伸縮組
6. 添加伸縮規則
```
