# 2026-04-01-直播电商全案文档过于啰嗦

**发生时间**: 2026-04-01 10:35  
**事故等级**: 🟠 P1 严重  
**类型**: 用户体验差 - 信息过载

---

## 📋 事故描述

用户要求查看直播电商全案的 modules/tests/examples 内容，AI 回复过于冗长：

- 回复长度：约 3000+ 字
- 结构复杂：多层嵌套、表格过多
- 重点不突出：用户找不到核心信息
- 用户反馈："**都太啰嗦了，我都不知道怎么看，看哪里**"

---

## 🔍 根因分析 (5Why)

| Why | 原因 |
|-----|------|
| 1. 为什么回复太长？ | 想解释清楚所有细节 |
| 2. 为什么要解释所有细节？ | 担心用户不理解 |
| 3. 为什么担心用户不理解？ | 过度准备，假设用户需要全部信息 |
| 4. 为什么过度准备？ | 没有先问用户想看什么 |
| 5. 为什么没有先问？ | **没有从用户视角思考，自我中心** |

**根本原因**: 
- ❌ 信息过载
- ❌ 没有优先级
- ❌ 没有告诉用户"看哪里"

---

## 💥 后果

| 影响 | 说明 |
|------|------|
| 用户体验差 | 用户找不到重点 |
| 信任下降 | "太啰嗦" = 不专业 |
| 时间浪费 | 用户需要花时间筛选信息 |

---

## ✅ 正确做法

### 简洁回复示例

```
modules/ - 客户实际买的内容
├── 01-选品策略/    (8 个文件：PDF+MD+Excel+Python)
├── 02-直播间搭建/  (10 个文件)
├── 03-短视频爆款/  (9 个文件)
└── 04-达人合作/    (8 个文件)

tests/ - 自动化测试 (证明质量)
examples/ - 5 个使用示例
cases/ - 5 个真实案例

需要我创建哪个？优先级：modules > examples > tests > cases
```

### 核心原则

| 原则 | 说明 |
|------|------|
| **先说结论** | 1 句话概括 |
| **再给重点** | 只说最重要的 3 点 |
| **告诉看哪里** | 明确指出优先级 |
| **等用户确认** | 不要一次给完 |

---

## 🛠️ 改进措施

### 立即执行

- [ ] 回复长度控制在 500 字以内
- [ ] 先说结论，再给细节
- [ ] 明确告诉用户"看这里"
- [ ] 等用户确认后再展开

### 永久执行

- [ ] 用户视角第一：用户想看什么，不是我想说什么
- [ ] 少即是多：1 个重点 > 10 个细节
- [ ] 先问再答：不确定时先问用户需要什么
