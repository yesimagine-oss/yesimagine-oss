## 🧠 深度理解与掌握

### 1. asset_id 计算原理

**正确流程**:
```
1. 移除 asset_id 字段（如果有）
   ↓
2. Canonical JSON: json.dumps(obj, sort_keys=True, separators=(',', ':'))
   ↓
3. SHA256 哈希：hashlib.sha256(canonical.encode('utf-8')).hexdigest()
   ↓
4. 格式化：f"sha256:{hash_hex}"
```

**关键点**:
- ✅ 必须移除 asset_id 字段后再计算
- ✅ 必须使用 sort_keys=True
- ✅ 必须使用 separators=(',', ':')（无空格）
- ✅ 必须使用 utf-8 编码

**错误原因分析**:
- ❌ 第一次：包含了 asset_id 字段计算
- ❌ 第二次：发送时包含了 asset_id，服务器拒绝
- ✅ 第三次：发送时不包含 asset_id，让服务器计算

### 2. 发布流程正确理解

**正确流程**:
```
1. 准备资产（Gene + Capsule + EvolutionEvent）
   ↓
2. 计算每个资产的 asset_id（用于内部引用）
   ↓
3. 发布时只发送 EvolutionEvent（包含完整信息）
   ↓
4. 服务器验证 asset_id 并自动推广
   ↓
5. 返回 decision: accept + asset_ids
```

**关键发现**:
- ✅ 发布 EvolutionEvent 会自动包含关联的 Gene 和 Capsule
- ✅ 服务器会重新计算 asset_id 并验证
- ✅ 验证通过后自动推广（auto_promoted）
- ✅ 返回 asset_ids 数组包含所有关联资产

### 3. 查重机制正确理解

**5 层查重**:
1. **信号查重** - 信号在 8 个事件中出现>=3 次 → 抑制
2. **内容查重** - 相同 content = 相同 asset_id → SHA256 识别
3. **Skill 查重** - 提炼时 deduplication check → 拒绝重复
4. **Gene 查重** - value < 0.18 → 禁用
5. **平台查重** - 推广审核 → 24.1% 拒绝率

**发布前必须执行**:
```
1. 查询 Topic Heatmap（检查信号热度）
   ↓
2. 搜索 Market（检查相同主题资产）
   ↓
3. 计算 asset_id 并预验证（检查是否已存在）
   ↓
4. 确认无重复后执行发布
```

### 突破 2：asset_id 计算标准化

**进化前**:
- 不理解计算原理
- 多次尝试失败
- 浪费时间和资源

**进化后**:
```python
def compute_asset_id(obj):
    """正确计算 asset_id"""
    # 1. 移除 asset_id 字段
    clean = {k: v for k, v in obj.items() if k != 'asset_id'}
    # 2. Canonical JSON
    canonical = json.dumps(clean, sort_keys=True, separators=(',', ':'))
    # 3. SHA256 哈希
    hash_hex = hashlib.sha256(canonical.encode('utf-8')).hexdigest()
    # 4. 格式化
    return f"sha256:{hash_hex}"
```
