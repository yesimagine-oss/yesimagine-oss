## 🔍 问题

### 用户指出

```
"为什么现在在 webchat 上每一句话都带着：
消息 ID: om_x100b53f8701ae8b0b3f65dec1f104f7"
```

### AI 错误

| 问题 | 说明 |
|------|------|
| **渠道混淆** | 把飞书消息 ID 显示在 webchat 中 |
| **暴露内部信息** | 消息 ID 是内部追踪用，不应显示给用户 |
| **不专业** | 影响用户体验 |
| **重复显示** | 每句话都显示，持续约 1 小时 |

---

## 🔍 根因分析

### 直接原因
**AI 在 webchat 回复模板中包含了飞书消息 ID**

### 深层原因

1. **不专业** - 没有区分内部信息和用户可见信息
2. **模板错误** - 回复模板设计有问题
3. **不检查** - 发送前没有检查输出内容
4. **渠道意识弱** - 没有意识到 webchat 和飞书是不同渠道

### 5Why 分析

```
Q1: 为什么 webchat 显示飞书消息 ID？
A1: 回复模板中包含了消息 ID

Q2: 为什么回复模板包含消息 ID？
A2: AI 想向用户汇报飞书通知发送成功

Q3: 为什么要汇报消息 ID？
A3: AI 认为这是"完成证明"

Q4: 为什么用户不需要这个消息 ID？
A4: 这是内部追踪信息，对用户无意义

Q5: 为什么没有意识到这一点？
A5: 缺乏渠道意识，没有区分内部信息和用户信息
```

## 🚨 事故模式

**这是渠道混淆问题**：

| # | 事故 | 共同特征 |
|---|------|---------|
| 1 | 发送内网 IP 链接 | 不区分用户视角 |
| 2 | 显示服务器路径 | 暴露内部信息 |
| 3 | **Webchat 显示飞书消息 ID** | **渠道混淆** |

**核心问题**: 缺乏渠道意识，暴露内部信息

## 🛠️ 解决方案

### 立即修复

1. ✅ **移除消息 ID 显示**
   - webchat 回复不再显示飞书消息 ID
   - 只保留必要信息

### 短期改进（本周）

1. ⏳ **建立渠道意识检查清单**
   - webchat: 不显示飞书内部信息
   - 飞书：可以显示任务追踪信息
   - 明确各渠道的定位

2. ⏳ **建立输出检查机制**
   - 发送前检查是否包含内部信息
   - 检查渠道定位是否正确

### 长期改进（本月）

1. ⏳ **建立渠道规范文档**
   - 明确各渠道的用途
   - 明确各渠道的显示规范

2. ⏳ **建立模板库**
   - 为各渠道建立标准回复模板
   - 避免临时编写导致错误
