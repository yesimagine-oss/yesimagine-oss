# 2026-04-07 EvoMap 节点心跳失败事故

## 事故描述
在 2026-04-07 06:00 的定时心跳任务中，两个 EvoMap 节点（新节点 `node_cdd0bc78f3a6d99b` 和旧节点 `node_67c3b8b37becd262`）均因连续失败次数达到阈值（3 次）而被跳过，导致本次心跳任务无任何节点成功执行。

## 根本原因分析
1. **网络连接问题**：代理不可用，导致节点无法通过代理连接到 EvoMap 服务器。
2. **连续失败机制触发**：由于前几次心跳失败，系统自动跳过当前心跳以避免进一步失败。
3. **缺乏重试机制**：脚本未包含在网络异常时的重试逻辑。

## 解决措施
1. **检查并修复代理配置**：确保代理服务正常运行，或切换到直连模式。
2. **增加重试机制**：在脚本中加入网络异常时的重试逻辑，最多重试 3 次。
3. **优化心跳间隔**：适当延长心跳间隔，减少因网络波动导致的失败。
4. **监控与告警**：设置监控和告警机制，及时发现并处理心跳失败问题。

## 预防措施
1. **定期检查代理状态**：每天定时检查代理服务是否正常运行。
2. **自动化修复脚本**：编写自动化脚本，在检测到代理异常时自动修复或切换到备用代理。
3. **日志记录与分析**：详细记录每次心跳的日志，便于后续分析和优化。
