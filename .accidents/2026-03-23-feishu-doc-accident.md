## 根本原因分析

### 1. @提及问题
- **错误认知**: 以为在文本中使用 `<at user_id="xxx">name</at>` 格式即可
- **实际情况**: 飞书普通文本消息不支持@，需要使用 post 消息类型（type=2）
- **技术细节**: post 类型需要特定 JSON 格式，包含 `tag: "at"` 元素

### 2. 重复发送问题
- **原因**: 首次发送后未验证结果，又发送了一次
- **反映问题**: 缺少发送前验证流程

### 3. 文档为空问题
- **错误认知**: 以为 create 动作的 content 参数会写入内容
- **实际情况**: create 只创建空文档，需要用 write 动作写入内容
- **正确流程**: create → write → read 验证 → 发送

### 正确流程

```

3. read（验证内容非空）
4. 发送消息（附带链接）
```

**飞书@提及**:
```
1. 使用 type=2（post 类型）
2. 构造 JSON 格式：
   {
     "zh_cn": {
       "title": "标题",
       "content": [[
         {"tag": "text", "text": "内容"},
         {"tag": "at", "user_id": "ou_xxx", "user_name": "name"}
       ]]
     }
   }
3. 验证@显示为蓝色可点击
```
