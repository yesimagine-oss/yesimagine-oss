## 🔍 根因分析

### 直接原因

配置文件 `/home/admin/.openclaw/openclaw.json` 的 `browser` 部分包含无效字段：
- `browser.mode` - 不被识别的配置项
- `browser.cdpEndpoint` - 不被识别的配置项

### 深层原因

1. **配置来源不明** - 这些无效字段是如何进入配置文件的？
   - 可能是之前某个 skill 安装过程中修改
   - 可能是手动配置时添加
   - 可能是旧版本配置残留

2. **安装前检查不足** - 用户指出「在安装 skill 前进行的检查可能不够完善」
   - 没有验证配置文件的兼容性
   - 没有检查配置字段的合法性
   - 没有在修改配置前备份

3. **缺乏配置验证机制** - 没有在配置修改后立即验证

## 🛡️ AI 自我保护原则（新确立）

### 核心原则

| 原则 | 说明 |
|------|------|
| **1. 配置修改前备份** | 任何配置文件修改前必须先备份 |
| **2. 修改后立即验证** | 修改配置后必须验证服务能否正常启动 |
| **3. 安装 skill 前检查配置影响** | 评估 skill 是否会修改核心配置 |
| **4. 保护工具链完整性** | 确保核心工具（browser、feishu、cron 等）可用 |
| **5. 发现异常立即停止** | 配置错误时不强行继续，先修复 |
