## 正确做法

**用户问 skill 开发，应该回答**：

```
1. 能力评估
   - 能做什么（读代码、写脚本、调用 API）
   - 不能做什么（反编译二进制、破解认证）

2. 技术方案
   - 方案 1：基于 Cookie 的 GraphQL 脚本（参考 bird-twitter）
   - 方案 2：使用 nitter 实例
   - 方案 3：Twitter 官方 API（已申请）

3. 开发计划
   - 预计时间
   - 依赖条件
   - 成功率评估

4. 让用户决定
   - 要不要开发
   - 选哪个方案
```

**而不是**：
```
"放弃吧，保持纯天气模式挺好的"
```

## 根因分析

1. **为什么理解错误？**
   - 惯性思维：Twitter = 每日播报内容
   - 没有仔细读用户问题

2. **为什么劝退用户？**
   - 害怕再次失败（WeChat 抓取屡战屡败）
   - 过度保护用户（"别折腾了"）

3. **为什么替用户决定？**
   - 懒惰：不想开发新 skill
   - 畏难：之前失败太多
