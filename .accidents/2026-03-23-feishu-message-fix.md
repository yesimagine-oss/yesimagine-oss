## 修复方案

### 1. 云文档空白

**问题：** feishu_doc create 后没有 write

**修复：**
```
create → write → read 验证 → 发送消息
```

**强制执行：**
- ✅ create 后必须 write
- ✅ write 后必须 read 验证
- ✅ 验证通过才发送链接

---

### 2. 内网链接

**问题：** 发送服务器本地路径、内网 IP

**修复：**
- ✅ 发送前验证链接可访问性
- ✅ 只发公网 IP/域名
- ✅ 内网链接明确告知用户无法访问

**禁止：**
- ❌ `172.16-31.x.x`
- ❌ `192.168.x.x`
- ❌ `10.x.x.x`
- ❌ `127.0.0.1`
- ❌ `/home/admin/...`

---

### 3. 认错人

**问题：** 群聊中张冠李戴

**修复：**
- ✅ 发送前查 TOOLS.md 人员对照表
- ✅ 核对用户 ID
- ✅ 不凭记忆

**人员对照表位置：** `TOOLS.md` → 人员关系对照表

---

### 4. @提及无效

**问题：** 
- 发送的@提及不生效
- 暴露用户 ID（隐私泄露）

**修复：**
- ✅ 使用 replyTo 代替@提及
- ✅ 不暴露 `ou_xxx` 格式用户 ID
- ✅ 不强行使用卡片消息

**唯一推荐方案：**
```
用户发消息 → 用 replyTo 回复 → 飞书自动通知
```

---

### 5. 消息格式混乱

**问题：** 纯文本/富文本/JSON 混用

**修复：**
- ✅ 统一使用纯文本
- ✅ 不发送 JSON 代码
- ✅ 不混用格式

## 强制执行清单

### 发送消息前

- [ ] **查人员对照表** - TOOLS.md
- [ ] **确认用户 ID** - 不凭记忆
- [ ] **确认群组** - 发到哪里？
- [ ] **确认内容** - 准确吗？

### 发送链接前

- [ ] **验证可访问** - 用户能打开吗？
- [ ] **验证类型** - 内网/公网？
- [ ] **说明限制** - 需要代理/登录？
- [ ] **如实描述** - 不夸大

### 创建文档前

- [ ] **create 后 write** - 必须写入内容
- [ ] **write 后 read** - 验证内容
- [ ] **验证通过** - 才发送链接

### @提及

- [ ] **只用 replyTo** - 不暴露用户 ID
- [ ] **不用卡片** - message 工具不支持
- [ ] **不发送 JSON** - 会显示为乱码
