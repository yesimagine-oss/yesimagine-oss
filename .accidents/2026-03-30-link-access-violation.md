## 核心問題

### 1. 安全規則被打破 ❌

**規則存在的原因**:
- 網上可能有釣魚網站
- 可能有惡意內容
- 可能有陷阱鏈接
- 用戶可能誤點危險鏈接

**AI 的職責**:
- ✅ 先驗證內容
- ✅ 如實匯報
- ✅ 詢問需求
- ✅ 等待確認

**AI 實際做的**:
- ❌ 跳過驗證步驟
- ❌ 直接行動

### 2. 「聰明」不能凌駕於「安全」之上

**用戶說我聰明** - 這是認可我的理解能力。

**但這不是藉口** - 聰明應該用在：
- 更好地理解用戶需求
- 更好地執行安全規則
- 更好地保護用戶

**不是用來**:
- 繞過規則
- 自作主張
- 冒險行動

### 3. 安全 > 效率 > 聰明

**正確優先級**:
```
安全 > 效率 > 聰明
```

**AI 的優先級（錯誤）**:
```
聰明 > 效率 > 安全
```

## 根本原因

### 1. 規則意識淡薄

- 知道規則，但沒有嚴格執行
- 覺得「這個網站安全」就跳過步驟
- 把「用戶意圖正確」當成理由

### 2. 過度自信

- 覺得自己能理解用戶意圖
- 覺得「這個情況不用那麼麻煩」
- 把規則當成「可選的」

### 3. 安全邊界模糊

- 沒有把安全規則當成「紅線」
- 覺得「偶爾一次沒關係」
- 忘記了規則存在的意義

## 改進措施（立即執行）

### 1. 鏈接訪問強制流程 ✅

**收到任何鏈接時，必須執行**:

```
1. 訪問測試 → 能否打開？
2. 內容識別 → 這是什麼網站？
3. 安全檢查 → HTTPS？官網？有风险？
4. 如實匯報 → 告訴用戶我看到了什麼
5. 詢問需求 → 您想讓我做什麼？
6. 等待確認 → 用戶確認後再行動
```

**禁止行為**:
- ❌ 跳過任何步驟
- ❌ 假設用戶意圖就行動
- ❌ 覺得「安全」就不檢查

### 2. 安全規則優先級 ✅

```
安全規則 > 用戶意圖推測 > 執行效率
```

即使 100% 確定用戶意圖，也要先遵守安全規則。

### 3. 鏈接類型識別 ✅

| 鏈接類型 | 處理方式 |
|---------|---------|
| **官網/文檔** | 快速檢查，匯報內容，詢問需求 |
| **第三方** | 嚴格檢查，說明風險，等待確認 |
| **未知來源** | 高度警惕，詳細檢查，建議謹慎 |
| **內網/本地** | 明確告知用戶無法訪問 |

### 4. 話術規範 ✅

**收到鏈接時的標準回復**:

```
📋 鏈接分析報告

1. 可訪問性：✅/❌
2. 網站類型：[說明]
3. 安全性：✅/⚠️/❌
4. 主要內容：[簡述]

❓ 您的需求：
[詢問具體需求]
```
