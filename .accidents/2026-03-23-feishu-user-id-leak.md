## 事故經過

### 用戶要求
用戶要求整理 OpenClaw 安裝指南到飛書文檔，並@机械师 查看。

### 錯誤操作

**第 4 次嘗試** - 使用卡片消息格式發送@提及：

```json
{
  "config": {"wide_screen_mode": true},
  "elements": [{
    "tag": "div",
    "text": {
      "content": "<at id=\"ou_382066265e530e2faad2433635178494\"></at>",
      "tag": "lark_md"
    }
  }]
}
```

### 問題現象

1. ❌ **JSON 直接暴露** - 消息未渲染，顯示原始 JSON
2. ❌ **用戶 ID 洩露** - `ou_382066265e530e2faad2433635178494` 直接顯示在群組
3. ❌ **隱私洩露** - 群組內所有成員可見用戶 ID

### 用戶反饋

> 未渲染，且暴露用戶隱私，群組內直接顯示了用戶 id，這屬於敏感信息

---

## 根本原因分析

### 1. message 工具不支持 interactive 卡片消息

- `contentType: interactive` 參數無效
- message 工具將 JSON 作為普通文本發送
- 飛書 API 需要通過 `im.message.create` 接口發送卡片消息

### 2. 用戶 ID 屬於敏感信息

- 飛書用戶 ID (`ou_xxx`) 是唯一標識符
- 不應該在公開場合暴露
- 可能被用於惡意用途（社工攻擊、權限提升等）

### 3. 未驗證消息渲染效果

- 發送前未測試卡片消息格式
- 發送後未立即檢查渲染結果
- 延遲發現問題（用戶提醒後才知道）

## 長期防範措施

### 禁止行為（永久記住）

| 行為 | 風險等級 | 禁止原因 |
|------|---------|---------|
| ❌ 在消息中直接寫用戶 ID | 🔴 最高 | 隱私洩露 |
| ❌ 發送未測試的卡片消息 | 🟠 高 | 可能暴露 JSON |
| ❌ 使用不支持的消息格式 | 🟠 高 | 渲染失敗 |
| ❌ 不驗證就發送 | 🟡 中 | 可能出錯 |

### 正確做法

#### 1. @提及的正確方式

**方案 A：使用飛書內建@功能**
- 在飛書客戶端手動輸入 `@机械师`
- 飛書會自動轉換為藍色可點擊提及
- 不暴露用戶 ID

**方案 B：申請應用權限**
- 在飛書開放平台申請 `im:message.group_at_msg:write`
- 使用正確的 API 調用方式
- 通過後台發送真正的@提及

**方案 C：使用 replyTo 功能**
- 回复用戶的消息
- 自動觸發通知
- 不暴露用戶 ID

#### 2. 卡片消息測試流程

```
1. 在測試群組測試格式
2. 驗證渲染效果
3. 確認無隱私洩露
4. 再在正式群組發送
```

#### 3. 發送前驗證清單

- [ ] **消息格式驗證** - 確認支持該格式
- [ ] **隱私檢查** - 無用戶 ID、Token 等敏感信息
- [ ] **渲染測試** - 先在小範圍測試
- [ ] **內容確認** - 無錯別字、格式正確
