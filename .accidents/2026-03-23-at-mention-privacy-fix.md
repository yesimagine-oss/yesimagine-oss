# @提及格式错误修复（隐私泄露）

**时间**: 2026-03-23  
**严重性**: 🔴 **最高（隐私泄露）**

---

## 📸 问题截图

**机器人发送的消息：**
```
<at id="ou_xxx">机械师</at>
```

**实际显示：**
- ❌ 不是蓝色可点击提及
- ❌ 显示为纯文本代码
- ❌ 暴露了用户 ID（`ou_xxx`）
- ❌ 群组成员都能看到用户 ID

---

## 🔴 严重性分析

### 隐私泄露风险

| 风险 | 说明 |
|------|------|
| **用户 ID 暴露** | `ou_f4919832188bcc630f8f257497fa93a4` 是唯一标识符 |
| **社工攻击** | 可能被用于定向攻击 |
| **群组成员可见** | 所有群成员都能看到该 ID |
| **违反隐私原则** | 违反了"用户 ID 绝不暴露"的红线 |

### 格式错误

| 问题 | 说明 |
|------|------|
| **不是真正的@** | 飞书不识别手动写的`<at>`代码 |
| **不会通知用户** | 用户不会收到@提醒 |
| **显示为乱码** | 群成员看到的是代码不是提及 |

---

## ✅ 正确做法

### 方案 1：使用 replyTo（唯一推荐）

**回复用户的消息：**
```
（点击用户消息 → 回复）
在的，需要什么帮助？
```

**飞书会自动通知用户，无需@**

**优点：**
- ✅ 不暴露用户 ID
- ✅ 用户会收到通知
- ✅ 飞书原生支持
- ✅ 显示正确

---

### 方案 2：飞书客户端手动@

**用户在飞书里输入：**
```
@RedOpenClaw
```

**飞书会自动转换为蓝色可点击提及**

**优点：**
- ✅ 飞书自动处理
- ✅ 不暴露用户 ID
- ✅ 显示正确

---

### 方案 3：申请飞书权限（长期）

**在飞书开放平台申请：**
- `im:message.group_at_msg:write` 权限
- 使用正确的 API 调用方式
- 需要管理员审批
