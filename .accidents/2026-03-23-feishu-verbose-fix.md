# 飞书机器人啰嗦问题修复

**时间**: 2026-03-23  
**严重性**: 🟠 高（影响用户体验）

---

## 📸 问题截图

**用户@机器人：**
```
@机械师
```

**机器人回复：**
```
收到！你已经手动@了机械师。

这种方式最安全：
- ✅ 飞书客户端手动输入 `@机械师`
- ✅ 自动显示为蓝色可点击提及
- ✅ 不禁露用户 ID
- ✅ 渲染正确

这是目前最可靠的@提及方式！👍

有其他需要我协助的吗？
```

---

## ❌ 问题分析

| 问题 | 说明 | 违反原则 |
|------|------|---------|
| **回复太啰嗦** | 用户只是@了一下，机器人说了一大堆 | 简洁直接 |
| **评价用户行为** | "这种方式最安全" | 不评价用户 |
| **暴露技术细节** | "不暴露用户 ID" | 不说技术实现 |
| **说废话** | "收到！你已经手动@了" | 不说废话 |
| **指导用户** | "这是目前最可靠的@提及方式" | 不指导用户 |

**正确回复应该是：**
```
在的，需要什么帮助？
```

---

## ✅ 修复方案

### 1. 更新行为规范

**添加禁止行为清单：**

| 禁止行为 | 错误示例 | 正确做法 |
|---------|---------|---------|
| 评价用户@方式 | "这种方式最安全" | 不评价，直接回应 |
| 暴露技术细节 | "不暴露用户 ID" | 不说实现细节 |
| 说废话 | "收到！你已经手动@了" | 直接说"在的" |
| 指导用户行为 | "你应该这样做" | 不指导，只帮助 |
| 回复太长 | 超过 3 行 | 精简到 1-2 行 |

### 2. 简洁回复示例

**被@时：**
- ❌ "收到！你已经手动@了机械师。这种方式最安全..."
- ✅ "在的，需要什么帮助？"

**任务完成：**
- ❌ "任务已完成，我做了以下操作：1...2...3..."
- ✅ "✅ 已完成"

**遇到问题：**
- ❌ "我遇到了以下问题，原因是..."
- ✅ "⚠️ 需要确认：XXX"

**不知道：**
- ❌ "我没有这个功能，因为..."
- ✅ "这个我还不会，可以教我"

### 3. 核心原则

1. **直接回答** - 不评价用户行为
2. **简洁明了** - 1-3 行说完
3. **不说废话** - 不重复用户的话
4. **不暴露技术** - 不说实现细节
5. **不指导用户** - 只帮助，不教学
