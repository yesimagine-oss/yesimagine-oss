# 2026-03-30 天气格式混乱事故

**发生时间**: 2026-03-30 19:08  
**发现时间**: 2026-03-30 19:10  
**事故级别**: ⚠️ 警告（格式问题）

---

## 📋 事故描述

**现象**: 飞书收到的每日播报中，天气格式混乱

**问题内容**:
```
🌤️ 济南：济南：+15C 51% 🌤️ 威海：威海：+7C 86%
```

**问题**:
1. ❌ 城市名重复（"济南：济南"）
2. ❌ 百分比难懂（51% 是什么？湿度？）
3. ❌ 格式不统一

**预期内容**:
```
🌤️ 济南 +15°C | 威海 +7°C
```

---

## 🔍 根本原因

### 1. 城市名重复

**原因**: `get_weather()` 函数返回时已经包含城市名，但 `generate_brief()` 又添加了一次

**问题代码**:
```python
# get_weather 返回
f"{city}: {weather_text}"  # 例如："济南：+15C 51%"

# generate_brief 使用
f"{city}: {get_weather(city)}"  # 结果："济南：济南：+15C 51%"
```

### 2. 百分比难懂

**原因**: 湿度（51%）对普通用户无意义

**问题**:
- 用户不关心湿度
- 百分比无标签（不知道是什么的百分比）
- 增加阅读负担

---

## ✅ 解决方法

### 修改 get_weather 函数

**修改前**:
```python
return f"{city}: {weather_text}"
```

**修改后**:
```python
return weather_text  # 只返回温度，不含城市名
```

### 修改 generate_brief 函数

**修改前**:
```python
weather_list = [f"{city}: {get_weather(city)}" for city in config['cities']]
```

**修改后**:
```python
weather_list = [f"{city} {get_weather(city)}" for city in config['cities']]
```

### 简化天气格式

**修改前**:
```python
resp = requests.get(f'https://wttr.in/{city_en}?format=%t+%h')
```

**修改后**:
```python
resp = requests.get(f'https://wttr.in/{city_en}?format=%t')
```

## 🙏 反思

### 错误

1. **未预览发送内容** - 生成后未检查就发送
2. **信息过载** - 添加了无用的湿度信息
3. **代码重复** - 城市名在多处添加

### 改进

1. **发送前必预览** - 检查格式和内容
2. **最小信息原则** - 只保留必要信息
3. **用户视角** - 从用户角度思考什么有用
